# 评测集（Eval Set）

这份评测集回答一个问题：**生成出来的东西，还像不像那个人自己讲的梦。**

不是跑分，不是榜单。每次改提示词、换模型、调参数，都要在同一批梦上重跑一遍，看三项分数有没有掉。

## 采集：每条梦记三样东西

1. **日期**——梦属于哪一晚（不是录入时间）。
2. **梦的原始口述记录**——本人醒来后对着手机讲的第一遍，逐字转写，**不改错别字、不补标点、不润色**。这是唯一的地面真值。
3. **时长**——这段口述有多少秒。用来判断「信息密度」：30 秒讲完的梦和 6 分钟讲完的梦，不该用同一把尺子量。

采集方式：直接用本 App 录，导出音频与转写文本；或事后补录（补录时必须凭记忆复述，并注明「补录」）。

## 脱敏（入库前必做）

真实梦境原文**永不入库**（`.gitignore` 已挡 `docs/eval/*.local.md` 与 `docs/eval/*.local/`）。进 git 的只有槽位和汇总分数。

确实需要放样例时，按下面替换：

| 类别 | 处理 |
|---|---|
| 人名 | 换成「A」「B」「一个朋友」「我妈」这类关系词，保留关系不保留身份 |
| 地名 | 换成「一个南方城市」「老家的楼」这类模糊描述；街道、小区、单位名一律去掉 |
| 单位名 | 换成「公司」「学校」「医院」 |
| 电话/身份证/车牌/账号 | 直接删除，不替换 |
| 可识别的独特事件 | 改掉一个不影响的细节（季节、职业、楼层），保留梦的结构 |

判断标准：**把这段文字给一个认识你的人看，他认不出这是你。**

## 评分：三项，各 1–5 分

对每条梦的「小说化」输出打分（原样稿不评，它只做转写质量检查）：

1. **像不像人写的**（1 = 一眼 AI，5 = 分不清是人还是模型）
   看：有没有排比堆砌、有没有「仿佛」「宛如」滥用、有没有总结陈词、有没有把感受解释一遍。
2. **有没有丢核心情节**（1 = 关键情节丢了或顺序乱了，5 = 该有的都在）
   对照原始口述逐句核。补写可以加细节，但不能替换或删除原有事件。
3. **有没有编造事实**（1 = 编了明显不存在的人/物/因果，5 = 没有无中生有）
   这是唯一「一票否决」的项：**任何一条出现编造，本次评测直接不通过**，不管另外两项多高。

补充记录：**编造次数**（本次 N 条里有几条出现了编造），以及自由文本「备注」（哪条崩了、崩在哪一句）。

## 门槛：先跑 10 条，攒到 20 条再提高

- 第一批只准备 **10 条**，跑通了流程、把评分口径磨一致，就算过。
- 攒到 **20 条**之后，才把通过线定死：三项均分 ≥ 4.0，且编造次数 = 0；10 条时代用 ≥ 8/10（设计文档 §14.4 的口径）。
- 样本少于 10 条时**不许下结论**——三条梦的均分说明不了任何事。
