# 评测集（Eval Set）

这份评测集回答一个问题：**生成出来的东西，还像不像那个人自己讲的梦。**

不是跑分，不是榜单。每次改提示词、换模型、调参数，都要在同一批梦上重跑一遍，看三项分数有没有掉。

## 采集：每条梦记三样东西

1. **日期**——梦属于哪一晚（不是录入时间）。
2. **梦的原始口述记录**——本人醒来后对着手机讲的第一遍，逐字转写，**不改错别字、不补标点、不润色**。这是唯一的地面真值。
3. **时长**——这段口述有多少秒。用来判断「信息密度」：30 秒讲完的梦和 6 分钟讲完的梦，不该用同一把尺子量。

采集方式：直接用本 App 录，导出音频与转写文本；或事后补录（补录时必须凭记忆复述，并注明「补录」）。

## 脱敏（入库前必做）

真实梦境原文**永不入库**（`.gitignore` 已挡 `docs/eval/*.local.md` 与 `docs/eval/*.local/`）。进 git 的只有槽位和汇总分数。

确实需要放样例时，按下面替换：

| 类别 | 处理 |
|---|---|
| 人名 | 换成「A」「B」「一个朋友」「我妈」这类关系词，保留关系不保留身份 |
| 地名 | 换成「一个南方城市」「老家的楼」这类模糊描述；街道、小区、单位名一律去掉 |
| 单位名 | 换成「公司」「学校」「医院」 |
| 电话/身份证/车牌/账号 | 直接删除，不替换 |
| 可识别的独特事件 | 改掉一个不影响的细节（季节、职业、楼层），保留梦的结构 |

判断标准：**把这段文字给一个认识你的人看，他认不出这是你。**

## 评价：三层，都不依赖"标准答案"

这套评价回答的不是"像不像某篇范文"，而是"**这次改动，是变好了还是变坏了**"。所以没有 1–5 分绝对评分。

用户提供的那两条亲笔例子（教室/北塔那两条）**不是标准答案**：它们本身有漏、有含糊、有笔误。把它们当对照目标，会把"照抄人的疏漏"评成合格，也会把"模型做得更好"评成扣分。它们只有两个用途——**下限尺子**（新稿"读得通"不许更差）与**口味参照**（信息密度、忌口、现场感）。

**第一层 · 规则闸门**（脚本 `scripts/check-faithful.py`，可执行，任一项红即本轮不通过）

| # | 判据 | 阈值 | 抓的是什么 |
|---|---|---|---|
| G1 | 输出里新出现的专名 / 数量 / 颜色 / 方位词 | = 0 | 模型偷偷加东西 |
| G2 | 长度比（输出字数 / 输入字数） | ≤ 1.10 | 理顺不会让文章变胖 |
| G3 | 原文关键名词与动词覆盖率 | ≥ 95% | 拿走的是口水，不是内容 |
| G4 | 跨场景因果连接词（于是/因此/所以/正因为/导致）跨段出现 | = 0 | 模型最爱偷偷"讲圆"的地方 |
| G5 | 不确定词（好像/记不清/大概/似乎/可能）保留率 | = 100% | 把梦的不确定改成确定 |

**第二层 · 盲评偏好**（不做绝对分）：同一篇梦出两版（保守版 / 放得开版），遮掉版本标签，只问两句——"更喜欢哪个""哪句过了"。只记选择与理由。理由要能落到句子，不写"更自然"。

**第三层 · 下限基线**：只在"读不读得通"上与用户那两条例子比，判据是"**不更差**"，不是"像不像它"。这一层只有一条红线：如果新稿比人手写的还难读，说明理顺这一步做坏了。

计数型硬指标（**编造次数**、**原样整理违规次数**）保留，**目标都是 0**，各自一票否决。它们的分母是"本轮实际跑了几条"，**不是"20 条样本"**——真实样本由用户随手提供，样本不足时不许下结论，但不许伪造，也不许因此停住开发。

## 门槛

- 第一轮只要求：**闸门全绿 + 流程能跑通**，不设条数门槛。
- 样本少于 3 条时**不许下结论**，只能在备注里写观察。
- 攒到 20 条是"可以开始看趋势"，不是"许可开工的前提"。

## 自动检查

`scripts/check-ai-flavor.py` 是**表面特征检查器**：只查可指认的 AI 写作症状（结尾升华、对偶句、三段式、破折号密度、段长均匀等），规则定义与正反例见 `docs/eval/anti-ai-patterns.md`。它不是分类器，不判断作者身份，也不替代下面的人工评分。

### 怎么跑

在仓库根目录：

```bash
# 自测样例：AI 腔应报错
python scripts/check-ai-flavor.py docs/eval/fixtures/ai-flavored-01.md

# 人写样例应通过
python scripts/check-ai-flavor.py docs/eval/fixtures/human-01.md

# 批量（PowerShell 不会替原生程序展开通配符，脚本自己展开）
python scripts/check-ai-flavor.py docs/eval/fixtures/*.md

# 机器可读；CI 里想临时放宽 HARD 阈值
python scripts/check-ai-flavor.py docs/eval/*.md --json --max-hard 2
```

输出格式：`文件:行号:列 编号 严重度 名称 | 命中片段`，末尾一行 `HARD=x MED=y SOFT=z`。

### 退出码

| 退出码 | 含义 |
|---|---|
| `0` | HARD 命中数 ≤ `--max-hard`（默认 0），通过 |
| `1` | HARD 命中数 > `--max-hard`，不通过 |
| `2` | 输入错误：文件不存在、通配符无匹配、不是合法 UTF-8 |

MED/SOFT 只计数，不影响退出码。`--max-hard` 只是临时放宽，**不要把它当成默认通过线**；发布前仍用默认 0。

### 和三层评价的关系

- 自动检查是**第一层闸门的一部分**：HARD > 0 的稿子先改，不进入偏好对比，省得浪费你的时间。
- HARD = 0 **不等于**「像人写的」。它只说明没踩到那 21 条表面规则；"读不读得通"仍要人眼过一遍。
- 命中数**不折算**成任何分数——本仓库没有分数这一栏。
- `docs/eval/fixtures/` 里的两个文件是**脚本自测样例**，不参与任何通过线统计。

### 当前状态

**真实梦境样本仍为 0。** 三层评价里，第一层（自动检查 + 单位测试）现在就能跑；第二层（盲评偏好）需要有稿子才能做；第三层（下限基线）只在有人手写的对照时才用得上。

因此现在的判定是：**样本为 0 不阻塞任何开发与验收**，只是"生成质量"这一项如实标成「未评」，不许写成通过。
