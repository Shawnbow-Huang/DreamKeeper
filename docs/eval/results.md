# 评测结果

每次改提示词、换模型、调参数，跑完一轮就往下表加一行。**空表不是占位，是"还没跑过"。**

口径见 [README.md](./README.md)。**这不是打分表。** 评价分三层，都不依赖"标准答案文本"：

1. **规则闸门**（脚本 `scripts/check-faithful.py`，可执行，任一项红即本轮不通过）；
2. **盲评偏好**（同一篇梦出两版、遮标选一个，只记选择与理由，不打分）；
3. **下限基线**（只用"读得通不通"跟用户那两条亲笔例子比，判据是"不更差"，不是"像不像它"）。

> 为什么不做 1–5 分：手里没有可直接对照的标准答案。用户那两条例子**本身有漏、有含糊、有笔误**，把它们当对照目标，会把"照抄人的疏漏"评成合格，也会把"模型做得更好"评成扣分。它们只当**下限尺子 + 口味参照**。

## 填表须知

- **版本**：提示词文件名 + 内容 sha256 前 8 位（例如 `novel.v2@a1b2c3d4`）。版本 = 文件名 + 内容哈希，见设计文档 §7.1。
- **样本数**：本轮实际跑了几条，不是槽位总数。**少于 3 条时不许下结论**，只能在备注里写观察。
- **五个闸门列**：填实测数值（`0`、`1.08`、`0.97`…），不是填"通过"。阈值是红线，数值本身有信息量——长度比 1.02 与 1.09 是两种不同的稿子。
- **编造次数 / 原样整理违规次数**：两条独立的一票否决项。编造说的是小说化那份稿子（无中生有的人、物、因果）；违规说的是原样稿（改了原话、合并了句子、加了原文没有的连接词、把"好像"改成"似乎"）。**各自 > 0，本轮就不通过**。
- **盲评偏好**：二选一加一句理由。理由要具体到句子（"第 3 段把跳跃处讲圆了"），不要写"更自然"这种没法用的评语。
- **备注**：哪条崩了、崩在哪一句。真实梦境原文**永不入库**，用槽位编号指代（如「#07 第二段多了一个不存在的妹妹」）。
