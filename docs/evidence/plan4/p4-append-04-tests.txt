== 为什么 ==
需求 A（用户随时语音续写）：点「补一段」录音 → 复用首段 WAV 尾部追加 → 只转写尾段 →
转写追平后自动重新理顺一次。T4 同时补上 T3 遗留的展示缺口：原样 tab 此前只显示
rawTranscript，有整理稿的梦看不到整理稿，也没有「看原始转写」的入口。

== 改法 ==
1. ui/nav/DreamRoute.kt：新增 `Append(dreamId)`（route = append/{dreamId}）。
2. ui/record/RecordViewModel.kt：新增 `appendDreamId`（非 null = 追加模式，starter.start 用既有 id，
   DONE 后只 `repository.beginAppend(dreamId, elapsedMs)`，不新建梦、不改路径）。
3. ui/record/RecordScreen.kt：新增 `appendDreamId` / `onAppendSaved`，保存成功后回详情而不是去追问页。
4. service/RecordingService.kt：收尾按 `createdThisTake` 分流——新建 take 走整段转写，
   追加 take 走 `enqueueAppend`（先 beginAppend 落库再排队，Voice AI 复核 ②）。
5. stt/TranscriptWriter.kt：新增 `onAppendRecordingFinished(dreamId, file, totalMs)`，
   beginAppend 0 行时最多等 5s 让 RecordViewModel 落库，再走既有 `onAppendFinished`（尾段切片）。
6. ui/detail/DetailViewModel.kt：`onAppendRecorded()`（幂等置位）、`canAppendNow()`（生成/改稿在飞时禁用）、
   `retryTranscription()`、`skipTranscription()`；state 收集里等 `status==OK && transcriptMs>=rawAudioMs`
   后自动 `generateFaithful()` 一次。
7. ui/detail/DetailScreen.kt：原样 tab 重写——整理稿正文（无整理稿时原文）、「看原始转写/看整理稿」切换、
   「还有 N 秒没转成文字」+「重试转写 / 这段不用转写」、「补一段」、「重新理顺」、整理中三态。
8. ui/DreamKeeperRoot.kt：`append/{dreamId}` 路由；DetailScreen 传 onAppend。
