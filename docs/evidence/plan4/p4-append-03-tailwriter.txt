# 为什么（T2）
追加录音只该把「新增尾段」送去识别；整段重转会把已转写文字再拼一遍。系统 STT 只有整文件入口
（SttEngine.transcribe(file)），所以先切一个只含 [transcriptMs, rawAudioMs) 的临时 WAV，再走同一条入口。
另外：进程被杀时「时长已落库、正文未拼」是常态 → 启动时按 rawAudioMs > transcriptMs 补转写。

# 改了什么
- 新 `stt/TailWav.kt`：复制 44 字节 canonical 头、只拷 [44+fromMs*32, EOF) 数据段；
  重写 RIFF/data 两个 size 字段（源文件占位期可能是 0xFFFFFFFF）；越界写合法空 WAV 并返回 0。
- `stt/TranscriptWriter.kt`：
  · `onAppendFinished(dreamId, file)` 读行决定 [T, A) 范围 → TailWav 切片 → 转写 → 后缀 CAS；
  · 在飞期间再次收尾记 `pendingRerun`，本轮结束后**重读行**补跑（用新水位，不会重复拼）；
  · `reconcilePending()` 扫「PENDING 且 A > T」的行补跑；FAILED 不自动重跑；
  · 尾段为空/识别无有效文字 → 只置 FAILED，正文与水位不动。
- `DreamDao.markAppendFailed(id, expectedMs)`（按 rawAudioMs 对齐、不碰正文/水位）+ `pendingAppends()`；
- `DreamRepository.appendTranscribed(...)` / `markAppendFailed` / `pendingAppends`；
- `DreamKeeperApp.onCreate`：audioScan 之后跑 `reconcilePending()`；
- `AppContainer.transcriptWriter` 注入 `cacheDir/stt-tail`（audio 目录里的 *.wav 会被 AudioScan 当孤儿恢复）。
