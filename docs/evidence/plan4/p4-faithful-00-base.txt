# 为什么（T3）
Plan 3 的忠实链只把整理稿写进 `novel_versions` 与 `dreams.novelText`，从不回写 `dreams.faithfulText`
（D394 的可见性判断因此只能用版本行）。小说化的「理顺稿」槽也一直与「原始转写」槽传同一个值，
等于把设计 §6.2「以理顺稿为底本」做成了「把原文抄两遍」。本任务把基座补正。

# 改了什么
- `dreams.faithfulText` 成为忠实链的落点：`GenerationStore.commitSuccess` 增第 5 个可选参数
  `faithfulTextForDream`，与版本行、`novelText`、`generationStage` **同一个事务**写入；
  `DreamDao.updateNovelAfterGeneration` 增一列 `faithfulText = COALESCE(:faithfulText, faithfulText)`
  （传 null = 不动，小说化/改稿都传 null）。
- `GenerationOrchestrator.novel()` 两槽分离：`【原始转写】= dream.rawTranscript`、
  `【理顺稿】= dream.faithfulText`（空则回退原文）；`filterChangeLog` 改「双基准」：
  quote 只要在理顺稿或原始转写的任一里逐字出现即保留。
- 忠实链 T3（保守档也失败）不建版本、不写 `faithfulText`（返回 `text=input`，语义等价），
  由调用方决定是否重跑；避免「失败也落库」。
