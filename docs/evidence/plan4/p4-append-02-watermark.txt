# 为什么补这条（T1 审计发现，D423）
原实现 save() 写 `transcriptMs = dream.transcriptMs`；domain 里该列默认 0，
因此任何「拿着旧 Dream 对象（或不认识新列的 caller）做整行保存」都会把水位抹回 0。
后果：下次追加会把已转写段重新拼进正文（重复文本），且 UI 认为整段音频未转写。
整行 save() 不是水位推进路径 —— 水位只由 appendTranscript / skipUncoveredAudio 推进。

# 改法
DreamRepository.save()：
  transcriptMs = existing?.transcriptMs ?: dream.transcriptMs
（有现存行时一律沿用库里的水位；只有新建行才采用调用方给的值。）
