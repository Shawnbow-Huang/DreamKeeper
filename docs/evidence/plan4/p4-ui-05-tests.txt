# T6b 证据：成本行 + 跨页进度表（先红后绿的「绿」与变异反证）

## 为什么改
生成请求原本挂在 `viewModelScope`：用户点完「生成」切走，请求被取消，回到页面看到 Idle——
等于白花钱、还可能让人再点一次（双份成本）。成本行与「跨页进度表」是同一件事的两面：
把「在跑」放在 ViewModel 之外，把「花了多少」从 `llm_calls` 读出来。

## 改法
- `GenerationTracker`（导航根持有）：按 dreamId 存 Running/Failed，成功后清空。
- `DetailViewModel(generationScope, tracker)`：launch 用容器 `generationScope ?: viewModelScope`；
  所有状态写入口收敛到 `publishPhase()`，本地 Flow 与 tracker 只写一处。
- 成本行：`LlmCallDao.sumCostByDream` → `DreamRepository.sumCostMicroYuan` → VM `costMicroYuan`；
  `costLabel(0)=null`（不显示），否则 `累计 ¥%.4f`。

## 新增用例（共 5 例）
1. `GenerationScopeTest.zeroCostHidesTheCostLine` — 0 微元不显示。
2. `GenerationScopeTest.microYuanIsShownWithFourDecimals` — 3200 → `累计 ¥0.0032`；123456 → `累计 ¥0.1235`。
3. `GenerationScopeTest.runningPhaseSurvivesOutsideTheViewModel` — tracker 默认 Idle、Set Running 后可见、别的梦不受影响。
4. `GenerationScopeTest.clearingAndFailingAreScopedPerDream` — Failed 可覆盖 Running、clear 只清一个 dreamId。
5. `AppendEntryTest.generation phase is published to the tracker` — 真 Room + 真 repo + 门闩 fake runner：
   生成在飞时 tracker 必须是 `Running(FAITHFUL,1)`，完成后回 `Idle`。
