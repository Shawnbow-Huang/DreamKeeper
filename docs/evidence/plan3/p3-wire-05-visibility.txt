# p3-wire-05-visibility（Task 9b 收尾 / D394：生成入口可见性口径）

## 为什么改

Task 9b 的 `hasNovelDraft = dream.novelText != null || versions.isNotEmpty() || novelVersion > 0`
把「原样整理」也算成小说稿：原样整理（faithful 链）成功会写一条 `promptId="faithful"` 的版本，
`dreams.novelText` 同时被写成整理稿 → 用户点一次「原样整理」后，「小说化」入口永久消失。
实测走查：seed-dream-4（无稿）顶部有「原样整理 / 小说化」两按钮；按 9b 的口径，整理成功后
`dreams.novelText != null`，两按钮都会消失（D394）。

## 改法

`DetailViewModel.kt` 新增顶层纯函数（可 JVM 直测）：

    internal fun hasNovelVersion(dream: Dream?, versions: List<NovelVersionEntity>): Boolean {
        if (versions.isNotEmpty()) return versions.any { it.promptId != "faithful" }
        return dream?.novelText != null || (dream?.novelVersion ?: 0) > 0
    }

`DetailScreen.kt` 的 `NovelTab(hasNovelVersion = hasNovelVersion(state.dream, state.versions))`。
口径：有版本行时只看提示词归属（`novel` / `novel_revise` 才算小说稿）；没有版本行时退回
Plan 1/2 老数据（`dreams.novelText` / `novelVersion`）。

## 用例（新增 3 例，`GenerationPhaseMappingTest`）

1. `faithful only version still offers the novel entry` —— 只有 faithful 版本 → `false`（仍露出入口）
2. `novel or revise version hides the generation entries` —— novel / novel_revise 版本 → `true`
3. `legacy dream without version rows falls back to novelText` —— 无版本行：raw-only `false`，
   `novelText` 非空 `true`，`novelVersion=3` `true`
