# p5-t5-reliability.txt — T5 可靠性四条（A1/A2/A3/A4）

## 为什么做
Plan 4 审阅留下的四条实现缺陷（不是环境限制，不能 PENDING）：
- A1 追加录音中途被杀 → `AudioScan` 只改 `rawAudioMs` 不改状态，启动补转写只扫 PENDING → 尾巴永不补。
- A2「重试转写」是死按钮：CAS 只认 `FAILED`，头部换了状态（OK 但有未覆盖尾巴）时 0 行；且 ViewModel 只改库不触发 Writer。
- A3 生成闸门只看 `transcriptStatus==OK && 原文非空`，半截原文可以进模型。
- A4 全仓库没有录音时长/剩余空间守卫（4h≈460MB）。

## 改法
1. `DreamDao.markAppendDetected(id, ms)`：`rawAudioMs=:ms`，并且 `CASE WHEN transcriptMs < :ms THEN 'PENDING'`；`AudioScan` 在「文件变长」时改走它（缩短/相等仍走 `fixAudioMs`）。
2. `markTranscriptionRetry` 放宽为 `status IN ('OK','FAILED') AND transcriptMs < :expectedMs`；`DetailViewModel.retryTranscription()` 命中行后调用注入的 `onRetryTranscription`；`AppContainer.requestTranscriptionRetry()` 用 `transcriptionScope` 跑 `writer.reconcilePending()`；`DreamKeeperRoot`/`MainActivity` 接线。
3. 生成闸门两处都加 `(rawAudioMs ?: 0) <= transcriptMs`：`GenerationOrchestrator.generatable`（统一文案「转写未完成或原文为空」）与 `DetailViewModel.generate()`（具体到「还有 N 秒没转成文字…」）。
4. 新 `audio/RecordingLimits.kt`：4h 硬上限 + 开录前 128MB 剩余空间；`RecordingService.startRecording` 空间不足 `session.fail` + `stopSelf`；`ActiveRecording.readLoop` 到上限自动 `stopRecording()`（只 post 一次）。
