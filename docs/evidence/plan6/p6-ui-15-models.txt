# 为什么做
用户 2026-11-01 02:52：「关于这个 api key 能连通并使用到什么模型，不能自动检测出来当前能用什么模型，
然后在下拉框里选择吗？同时，除了小说化需要设置一些关于模型的参数，难道第一个模式就不需要了吗？」

# 改法
1. 模型自动检测：单家详情页右上「检测可用模型」→ GET {baseUrl}/models（Bearer）；
   兼容 data[].id / model / name 与 models[] 两种形状；10s 超时、单次、无重试、不写库。
   失败一律降级（很多兼容端点不实现 /models），把原因显示在按钮下方，不冒充鉴权错误。
2. 候选持久化：检测结果写 `dk_generation_models.<wire>`（逗号分隔），与内置清单合并为候选；
   检测**不改当前选择**——点它只是问「有什么」，选不选是下一步。
3. 双模型：设置页同时给「小说化模型」与「忠实整理模型」；忠实默认跟随小说化，可单独选便宜的；
   忠实链请求体用 faithfulModel，`llm_calls.model` 与价卡重算也用实际请求的模型。
4. 忠实链思考仍固定关闭（设计 §9：逐字保守），UI 只写一句说明，不给假开关。

- 第一张：小说化模型（Flash / V4 Pro）+ 右上「检测可用模型」+ 忠实整理模型（同为 Flash / V4 Pro）。
