# 一、生成链在真机上完全打不开（第三个真机 bug）
点「原样整理」立刻失败，界面只有「没生成成：转写未完成或原文为空」。
加日志后（`DreamGen` tag）：
W DreamGen: gate blocked: status=OK rawMs=92300 transcriptMs=0 textLen=424
→ `GenerationStore` 的 `DreamEntity.toDream()` **漏映射 `transcriptMs`**，领域模型恒为 0，
   `generatable()` 的「rawAudioMs <= transcriptMs」永远不成立 → 所有带录音的梦都被判「转写未完成」。
修复：`GenerationStore.kt` 补 `transcriptMs = transcriptMs`；新增回归用例
「有录音的梦：RoomGenerationStore 必须带回 transcriptMs 否则永远过不了闸门」。

修复后真机实测（同一篇 92.3 秒录音、423 字原样稿）：
D DeepSeekClient: DKLLM attempt n=1 kind=FAITHFUL status=ok http=200
D DeepSeekClient: DKLLM attempt n=1 kind=NOVEL status=ok http=200

# 二、两个模式不再是「点了小说化才出现」
- 原样 tab：顶部直接有「原样整理」；标题行写「原样稿 / 看原始转写」。
- 小说化 tab：只有「小说化」，不再出现「原样整理」。
- 两个动作各归各栏，互相独立（小说化内部仍会先跑一遍整理链拿基座，但入口不再互相遮挡）。

# 三、术语统一
用户可见文案统一为「**原样整理** / **原样稿**」：
- 设置 → 模型：原「忠实整理模型」→「原样整理模型」；说明改「原样整理只做『补标点、顺语序』……」
- 详情：原「整理稿」→「原样稿」；「看整理稿」→「看原样稿」；「正在理顺…」→「正在原样整理…」
- 代码/提示词内部的 `faithful` 命名保持不变（契约与 promptId 是审计字段，不跟着 UI 改）。
