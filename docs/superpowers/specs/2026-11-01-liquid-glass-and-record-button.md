# 液态玻璃质感 + 「说梦」按钮改色 —— 只读分析结论

**日期**：2026-11-01
**范围**：只读分析，本文不含代码改动。所有数值取自 `docs/evidence/plan6/*.png` 的实测像素与 `ui/theme/*.kt` 现有 token。
**约束**：零新依赖（只用 `compose-ui` / `foundation` 已有的 `drawWithCache`、`Brush`、`drawArc`）、minSdk 26、compileSdk 37。
**证据**：`p6-skin-01-{lamp,morning,indigo}-home.png`、`p6-skin-02-{lamp,morning,indigo}-settings.png`（1080×2400）。

---

## 0. 先说一个前提：这个 App 没有「背后的内容」

真正的液态玻璃（iOS 26 那套）靠的是**折射**：底下的东西被弯折、被糊掉、被染色。这个能力要求「玻璃」下面**真的压着内容**。

逐屏核对现状：

| 屏 | 玻璃候选元件 | 它背后实际是什么 |
|---|---|---|
| 日历 | 说梦钮 | 月水印 `Text`（200sp，`paper@0.055`）的一角 + 大片纯 `night` |
| 日历 | 底部「日历 / 全部」栏 | **什么都没有**（`Scaffold.bottomBar`，`NavHost` 拿到 `Modifier.padding(padding)`，内容根本滚不到它下面） |
| 全部 | 列表卡 / 分段控件 | 纯 `night` |
| 设置 | 三张分组卡 | 纯 `night` |
| 详情 | 改稿输入条 | **什么都没有**（`ReviseSheet` 是 `Column` 的最后一个子项，`.background(DreamColors.night)`，正文在它**上方**自己的 `weight(1f).verticalScroll()` 里滚） |

结论：**当前 0 处存在可被折射的背景**。所以「液态玻璃」在这个 App 里只能是**材质**（内高光 + 渐变描边 + 极低 alpha 底 + 噪点），不能是**折射**。这不是妥协，是准确定义——把「玻璃」当材质做，任何一个平面都能放；当折射做，必须先重构布局才有意义。

需要「透」的效果只有两处能做，代价写在第 1 节。

## 1. 「液态玻璃」加在哪（3 处，按优先级）

### #1 说梦键 —— 必须做，且不依赖背后内容

形状 `CircleShape` / 76dp。这是全 App 唯一主行动，也是唯一允许「有光感」的元件，玻璃材质在这里承担的是「一颗真的玻璃扣子压在纸上」的物理感。

圆角：`CircleShape`（= 38dp 半径）。

### #2 详情页小说 tab 的改稿输入条 + 版本线容器 —— 唯一能做出「透」的地方

需要一步**局部结构改动**（只在小说 tab 这一个 composable 内，约 10 行）：

- 现状：`Column { GenerationActions; Row(补写N处); Box(weight(1f).verticalScroll()) 正文; AskBubble...; ReviseSheet }` —— 输入条是堆叠的尾巴。
- 改成：`Box { Column(fillMaxSize, verticalScroll, contentPadding = bottom = 输入条高度) … ; ReviseSheet(align = BottomCenter, dreamGlass(顶部 20dp 圆角)) }`。

改完，小说正文会从输入条**下面**穿过——玻璃这时才有东西可透。这也是 iOS 输入条的标准做法。圆角：顶角 20dp、底角 0（贴边）。

### #3 底部「日历 / 全部」栏 —— 次优先，需要重构才成立

要让它有意义，必须让日历网格滚到栏下面去：

- `Scaffold(contentWindowInsets = WindowInsets(0))` 不再消费 bottom inset；
- `NavHost` 不再吃 `padding(bottom = barHeight)`；
- 每个屏自己加 `contentPadding.bottom = barHeight + navigationBar`。

这是跨屏改动（5 个屏 + 根），收益是「栏浮在网格与水印之上」。**如果这一轮不想动结构，直接砍掉 #3**，把预算给 #1 和 #2。圆角：顶角 20dp。

### 每处的四层做法

| 层 | 做法 | 深色（灯下纸 / 冷夜） | 浅色（晨光纸） |
|---|---|---|---|
| L1 底色 | `background(color, shape)` | `nightRaised @ 0.62` + `ember @ 0.04` 叠一层（≈ `#16171B`） | `paper @ 0.03`（墨洗，≈ `#EEE8DC`）；**禁止**用 `paperSurface`（见 §3.1） |
| L2 渐变描边 | `border(1.dp, Brush.linearGradient(topLeft→bottomRight), shape)` | `#FFFFFF 0.20 → 0.02`（凸起 emboss） | `#FFFFFF 0.58 → paper 0.10`（压印 deboss） |
| L3 内高光 | 顶部单侧短线/短弧，两端渐隐，`strokeWidth = 1.5dp` | `#FFFFFF @ 0.13`，长度 42% 宽 | `#FFFFFF @ 0.34`，长度 55% 宽 |
| L4 噪点 | `drawWithCache` 里预生成 `Array<Offset>`，画 0.5dp 白点 | `#FFFFFF @ 0.022–0.030`，格距 36dp | **0（禁用）** |

圆角与尺寸区间：

- 说梦键：`CircleShape`，76dp（触控 + 留白盒 112dp，不再是 132dp）
- 改稿条：顶角 20dp，高约 120dp（含 6 个快捷胶囊）
- 底栏：顶角 20dp，高 56–64dp
- **玻璃只用在 ≥64dp 的元件上**；≤36dp 一律不用（四层在 36dp 上分辨不出来，只会变成脏边）

### 坚决不要加的地方

1. **`DreamCard` 列表卡 / 设置页三张分组卡** —— 背后是纯 `night`，玻璃退化成「一层灰 + 一条边」；且晨光纸下卡的 `ΔL*` 本来只有 2.4（§3.1），叠玻璃只会更脏。
2. **正文 / 小说稿纸面 / 日记** —— 文字对比度是硬指标。alpha 底 + 噪点直接吃掉可读性，且玻璃后若有文字会「两层字叠印」。
3. **搜索 pill** —— 它是假输入框，玻璃会跟说梦键抢「全屏唯一的玻璃」，两个都不显眼。
4. **胶囊 chip（关/低/高/最高）、版本线 chip、tab 下划线、`LayoutSwitch`** —— ≤36dp，见上。
5. **录音全屏页 `RecordScreen` 的大圆** —— 已有实心 `emberDeep` + 动效，玻璃会削弱「按住」的物理确定性。
6. **任何页面转场、弹层、Snackbar** —— `DreamMotion` 契约是「夜间不做长动画」，玻璃的静态四层不需要动画，别引入。
7. **不要做真模糊** —— `Modifier.blur` 在 API 26–30 是 no-op（本 App minSdk 26），同一个 APK 会在 4 个系统版本上呈现两种视觉；自己写 `RenderEffect` 分支则每帧重绘整块区域，低端机直接掉帧。
   取舍：**放弃折射，得到磨砂膜**。全版本一致、零帧成本、可截图回归。若一定要「透」，唯一可控做法是背后内容 `graphicsLayer { scaleX = 1.06f; scaleY = 1.06f }` 做视差透，不是模糊透。

## 2. 「说梦」按钮为什么违和，以及两个替代方案

### 2.1 现状实测

`CalendarScreen.kt:131-159`：

```
Box(132.dp)  .background(Brush.radialGradient(
                 0.0f  to ember @ 0.30,
                 0.55f to ember @ 0.10,
                 1.0f  to Color.Transparent))
  └ Box(76.dp).background(ember, CircleShape) { Text("说梦", onLamp, titleMedium SemiBold) }
```

像素实测：

| 皮肤 | 圆盘填色 | 圆盘 L* | 光晕峰值 L* | 页面底 L* | 光晕 ΔL* |
|---|---|---|---|---|---|
| 灯下纸 | `#E2A24E` | 71.3 | 9.6（+110px 处） | 3.0 | **+6.6（是光）** |
| 冷夜 | `#C8873F` | 61.6 | 10.7 | 5.0 | **+5.7（是光）** |
| 晨光纸 | `#B06524` | 50.3 | **90.8（+120px 处）** | 94.26 | **−3.5（是污渍）** ← 反了 |

### 2.2 五条违和原因

1. **它违反这个项目自己写下的契约。** `theme/Color.kt:44-45` 原文：「`EmberDeep`：只做 ≤2dp 描边或 **≤8% 晕**，永远不做大面积填充」。现在的光晕是 `ember @ 0.30`，**上限的 3.75 倍**。
2. **圆盘不是光，光晕也不是光。** `Color.kt:8` 说 ember「**只作光**」。光的判据是「有方向、有衰减、面积大而极淡」——一颗 76dp 实心圆三条全不满足（无方向、无衰减、色块）；补的那个光晕又是**各向同性的同心环**，也不满足「有方向」。两半都错，所以拼起来不像灯，像「深色 SaaS 的录音按钮」。
3. **衰减曲线是错的。** `radialGradient` 中心 0.30、0.55 处 0.10；但圆盘只盖住外盒半径的 0.288——**可见段的峰值（0.30）恰好落在圆盘边缘**，于是先是一道硬边光，再拖一条 100px（≈37dp）几乎线性的长尾。真实灯具在漫反射纸面上**根本不该有环**：纸被灯照到，是纸面本身的亮度梯度，不是物件周围的一圈光环。
4. **浅色皮肤下物理不成立。** 见上表：同一个函数在晨光纸上产出 **ΔL* = −3.5、色相偏橙的环**。光不可能比纸更暗。它落在「能看见，但不像光」的区间——**正好是污渍的定义**。这就是用户看到的「违和」的一半。
5. **层级错位 + 一个真 bug。** 全屏只有它一条软边（其余全是 1dp 硬线 + 平涂），它像异物；而页面下方 39% 是空的，光晕无处可落，只能浮在虚空里。另外：晨光纸下 `onLamp #FFF8EE` 落在 `#B06524` 上实测 **4.21:1** —— 16sp SemiBold 不算大字号（阈值 18.66px bold），**AA 要求 4.5:1，这里是失败**。这是个 bug，不是风格选择。

### 2.3 方案 A「灯罩玻璃扣」（推荐）

保留实心琥珀核——因为「说梦」是全 App 唯一主行动，而下方 39% 屏高是空的；去掉实心核，日历页上就再没有任何暖色体重，视觉锚点消失。**只删光晕，加玻璃罩。**

由下至上：

| 层 | 内容 | 深色 | 浅色 |
|---|---|---|---|
| L0 | 接触阴影 | 无（近黑底上阴影无效）；改在 r+6dp 处一圈 `ember @ 0.10`、0.5dp | `paper @ 0.16` 圆，下移 3dp，半径 +2dp |
| L1 | 暖色核 | `ember` `#E2A24E` | `lerp(ember, emberDeep, 0.30)` = `#A55D20`（实测 4.76:1 ✓ 修掉 AA 失败） |
| L2 | 上沿高光弧 | `#FFFFFF @ 0.13`，1.5dp，arc 195°→345°（左上到右上），`StrokeCap.Round` | `#FFFFFF @ 0.34`，同角度 |
| L3 | 下沿暗弧 | `#000000 @ 0.16`，1.5dp，arc 20°→160° | `paper @ 0.12`，同角度 |
| L4 | 噪点 | `#FFFFFF @ 0.022`，36dp 格距 | 0 |
| L5 | 文字 | `onLamp` `#FFF8EE`，16sp SemiBold | 同（配合压暗后的核） |

尺寸 76dp / `CircleShape`；按下 `graphicsLayer { scaleX = scaleY = 0.96f }`，`tween(DreamMotion.Quick)`=120ms；`indication = null`（自绘按下态，不要 M3 ripple 在实心圆上铺一层黑）。

净改动量：删掉 132dp 的 `Box`+`radialGradient`，加 3 条 `drawArc` + 1 个 `animateFloatAsState`，`CalendarScreen.kt` 里约 +25 行，**不新增文件、不动主题**。

### 2.4 方案 B「压印灯芯」

无实心填充，ember 只以**描边 + 文字**存在。

| 层 | 内容 | 深色 | 浅色 |
|---|---|---|---|
| L0 | 底 | `ember @ 0.10` over night = `#1B1410` | `paper @ 0.03` = `#EEE8DC` |
| L1 | 渐变环 1dp | 上 `ember @ 0.55` → 下 `ember @ 0.12` | 上 `ember @ 0.30` → 下 `paper @ 0.12` |
| L2 | 内高光 | 上沿 1.5dp `#FFF4E2 @ 0.16` | 上沿 1.5dp `#FFFFFF @ 0.34` |
| L3 | 文字 | `ember` 在 `#1B1410` 上 **8.24:1** ✓ | `emberDeep #8A4B16` 在 `#EEE8DC` 上 **5.21:1** ✓（用 ember 只有 3.41:1 ✗） |
| L4 | 按下态 | 环 0.55→0.30 + scale 0.97 | 同 |

场合：只有当「说梦」不再承担唯一主行动时（比如加了锁屏/通知/快捷方式分流之后）才成立。

### 2.5 推荐 A，三条理由

1. **锚点**：页面下半是空的，实心核是唯一的暖色体重。B 的 ember 只剩 1dp 环 + 16sp 字，在近黑底上总视觉权重不足，说梦会变成「又一个控件」。
2. **改动面**：A 是删除式改动（25 行，零新文件），B 需要先有完整 glass 基础设施才好看，属于「下一轮」。
3. **语言冲突**：B 在晨光纸上就是「20dp 圆角 + 1dp 描边 + 墨色字」——和设置页 chip（`SettingsScreen.kt:189-191`、`464-466` 完全同构）。主行动和筛选控件长得一样，是比配色更大的问题。

## 3. 浅色皮肤（晨光纸）为什么容易脏 / 糊，以及规避规则

### 3.1 根因：晨光纸的层级本来就是靠描边，不是靠明度

实测（截图取样）：

| 皮肤 | 页面 L* | 卡片 L* | ΔL* | 对比度 |
|---|---|---|---|---|
| 灯下纸 | 3.03 | 10.86 | **7.83** | 1.28:1 |
| 晨光纸 | 94.26 | 96.65 | **2.39** | **1.06:1** |

晨光纸的面与面之间只差 **2.4 个 L\***——低于「可辨」阈值。也就是说：**晨光纸现在根本没有明度层级，所有层级都靠那根 1dp `line #D8CBB4` 撑着。** 在这个底子上再叠一层玻璃，玻璃能贡献的只有「又一条 1.06:1 的边」和一点让整块变浑的 alpha —— 纯亏。

**这是必须先修的前置条件。** 两个方向，推荐第二个：

- 提亮纸底（把 `paperSurface` 推到 `#FFFDF7`）→ 仍只有 ΔL* ≈ 4.3，不够，且纸会开始发白、失去「晨光」的暖。
- **反过来：卡片用墨洗。** 晨光纸的「纸比卡亮」= 卡片是压进去的（外部光强于内部），物理上成立、也更像纸。实测 `paper #2C2419` 按 alpha 叠加在 `night #F4EEE2` 上：

| 墨洗 alpha | 结果色 | ΔL*（相对 94.26） |
|---|---|---|
| 0.030 | `#EEE8DC` | −2.10 |
| 0.045 | `#EBE5D9` | −3.16 |
| 0.060 | `#E8E2D6` | −4.21 |
| **0.080** | `#E4DED2` | **−5.63** ✓ |

→ 晨光纸的卡/玻璃底统一取 `paper @ 0.06–0.08`，**不要**用 `paperSurface`。

### 3.2 十条规则与阈值

1. **ΔL\* 门槛**：同屏相邻层级 ΔL\* ≥ 5 才可辨，主层级 ≥ 9。当前晨光纸是 2.4 → 先做 §3.1 的墨洗，否则别加玻璃。
2. **浅色玻璃必须「压印」，深色才「凸起」**。浅色上沿 `#FFFFFF ≥ 0.55`、下沿 `paper ≤ 0.12`；顺序不可反（反了是塑料凸起，纸没有这个物理）。深色反过来：上沿白 `0.20`、下沿白 `0.02`。
3. **浅色玻璃底 alpha ≤ 0.10（墨）或 0**。**禁止** `paperSurface` 当玻璃底（ΔL* 2.4 = 没画，还多一层绘制）。
4. **浅色噪点 = 0**。阈值：1px、α ≥ 0.01 的暗点在 `#F4EEE2`（L*94）上肉眼即可辨认为霉点/毛屑。深色 0.02–0.035，且只在 ≥64dp 面积上。
5. **玻璃正下方 30dp 内不得有正文**。量化「糊」：玻璃后文字行高与玻璃内文字行高重叠 ≥ 30% 时必糊（像素级显形 + 两层字叠印）。
6. **玻璃上文字对比度按最坏情况算**：与「背后最亮元素」按 alpha 混合后的底色 ≥ 4.5:1，**不是**与设计底色算。浅色尤其致命——任何白卡都会把玻璃底从 L*94 拉到 97。
7. **同屏只允许 1 处玻璃**；一层玻璃只有**一个**高光方向（左上），全 App 统一。两处玻璃 = 两处都在说「我是浮起来的」，等于都没浮起来。
8. **不做真模糊**（§1.7 的取舍）。要做「透」就用 `graphicsLayer` 微放大到 1.06 做视差透。
9. **面积阈值**：玻璃只用 ≥64dp 的元件（说梦 76dp ✓ / 底栏 56–64dp ✓ / 改稿条 ~120dp ✓）；≤36dp 一律不用。
10. **晨光纸不用 ember 做玻璃**。ember `#B06524` L*=50.3，纸 L*=94.3，ΔL*=44 → 一块硬色块，且直接突破 `Color.kt:45` 的「≤8% 晕」契约。晨光纸的强调只能落在**文字与 1dp 线**上。

## 4. 是否需要新增生图元素

### 4.1 现状：4 张插画是「暗板」，在晨光纸上就是 4 个黑洞

`android/app/src/main/res/drawable-nodpi/`：`illus_library_empty` / `illus_day_empty` / `illus_novel_empty` / `illus_media`（均为 WebP，480×720 或 720×405/720×480）。

四张的共同语言：近黑底（实测背景接近 `#0A0A0C`，L* ≈ 2–3）、单一琥珀细线反光、纸纹/木刻颗粒、无文字无人物。这是按 `docs/superpowers/plans/2026-10-31-plan5-polish-and-assets.md:51` 那条「**为深色界面而作**／近黑 `#0B0E13` 底占画面 ≥50%」的 prompt 生成的。

在晨光纸 `#F4EEE2`（L*94.3）上，它们是 L*2 的方片，对比度约 **19:1**，比屏上任何文字都抢眼；`EmptyState` 还给了 168dp 宽。这确实不搭。

### 4.2 先不加图：把插画改成「贴在纸上的一张照片」

最小改动、零新资产、也不会破 CI。在 `ui/common/EmptyState.kt:39-44` 那个 `Image` 外面套一个容器（约 8 行）：

- 固定 4:3、宽度 168dp（沿用现宽）
- `clip(RoundedCornerShape(10.dp))`
- `background(DreamColors.night)`（深色插画的「相纸」）
- `border(1.dp, DreamColors.paper.copy(alpha = 0.10f))`
- 下方 8dp 的 `paper @ 0.06` 压印阴影

效果：浅色皮肤下它读作「纸上贴着一张夜里的照片」——**有意的**，而不是「图片忘了做亮版」。深色皮肤下容器几乎不可见（`night` 与插画底同色），视觉零变化。

**推荐先做这个。** 四条新插画 = 4 × 60KB 的黑洞，而且下面 4.3 那些约束一条不对就会退回现在的样子。

### 4.3 真要生图：先算 CI 代价

`android/app/src/test/java/com/dreamkeeper/assets/AssetCatalogTest.kt` 有两条硬断言：

- `drawableNodpiWebpSetEqualsCatalog`（:64-71）：`drawable-nodpi` 的 WebP 集合必须**恰好等于** `expected` 那 4 个名字（防孤儿/漏提交）。
- `totalIllustrationBudgetIs400kb`（:58-61）：4 张合计 ≤ 400,000 B；单张 ≤ 120,000 B（:50-55）。

所以加 4 张浅色版必须**同 PR** 改这两条：`expected` 扩到 8 个名字、总预算提到 ≤ 960,000 B（8 × 120KB）。否则 CI 必红。这也是一个真实成本，写进估算。
