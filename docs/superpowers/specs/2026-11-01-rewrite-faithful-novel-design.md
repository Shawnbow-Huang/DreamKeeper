# 提示词工程重写：原样整理 v3 与小说化 v3

- 日期：2026-11-01
- 状态：设计已与用户逐段确认（原样整理契约 / 小说化自由 / 三段式架构 / 数据与兼容）
- 范围：提示词、闸门、编排、设置项、数据结构与 UI 文案；不改数据库表结构
- 前置：0.11.4（真机生成链已修复）

## 1. 背景与问题

### 1.1 用户原话

> 「（原样整理）还是会出现很多表达重复意思的语句，还是有很多冗余，还是留下来了很多语气词，远远达不到我最初的『忠实记录梦里发生的事情，要简洁、精炼、准确，像流水账那样』的要求。」
>
> 「（小说化）写的内容没有世界观，没有故事性，没有连贯性，也不知道想要表达什么主旨。同时文笔极度的差……我在小说化这个模式下，是允许你大规模修改内容的，原样稿给你，只是借用原样稿的一些人物、事件、故事发展，看看是否能给你一些灵感，如果没有，也就可以舍弃那些。」

### 1.2 根因（不是模型不行，是契约与闸门互相拉扯）

| 证据 | 数字 |
|---|---|
| 拿用户 92 秒录音（380 内容字）模拟一份合格的 170 字流水账，跑现有 v2 闸门 | `G2=0.447`（要求 ≤1.10）、`G3=44.9%`（要求 ≥95%）、`G1/G5/G6` 均红 |
| 现有 faithful 提示词可删清单 | 只 5 类，且「留在永远比删错安全」 |
| 现有 novel 事实契约 | 禁止改人物关系/结局/关键事件；`G3` 要求原词保留 ≥95%；`G2` ≤110% |

结论：**v2 的闸门在物理上禁止「简洁」和「自由改编」**。只改提示词会被闸门打回；必须同时换闸门。

### 1.3 用户已确认的决策

| 决策 | 选择 |
|---|---|
| 原样整理底线 | **B：事实不改，措辞重写**（人物/地点/事件/顺序/因果/结局/数字/专名/不确定词不动；句子可合并、压缩、重写） |
| 小说化自由度 | **A：素材自由**（可删事件、换结局、改关系、新建世界观；保留梦的 DNA） |
| 小说产出规格 | **模型自选**，800–5000 内容字 |
| 原样整理思考档位 | **四档可调，默认「低」** |
| 小说改动清单 | **创作手记**（借用/舍弃/新造/主题），不再要求 quote 是原文子串 |
| 重写路线 | **v3 双提示词重写 + 闸门换血** |
| 小说生成架构 | **三段式精修**：规划 → 写作 → 逐行润色 |
| 参考 skill | 全文打包进 assets，按阶段注入**英文原件**（不翻译）；中文语言相关检查由我们自写 |

## 2. 目标与非目标

### 目标

1. 原样整理稿：事实完整、无口水、无元话语、无冗余，长度压到原文的 60–75%，读起来像流水账。
2. 小说化：有自洽世界规则、有欲望/阻碍/转折、有主旨、文笔达到可读的文学短篇；允许与原梦大幅不同。
3. 两套契约各自独立：原样整理的「保守」不再约束小说化，小说化的「自由」不污染原样整理。
4. 全部机器可校验：能自动判红的项必须自动判，不靠「模型自觉」。

### 非目标

- 不做通用 agent / 工具调用循环；三段式是固定流水线。
- 不做多轮对话式创作（现有改稿对话保留，不在本次范围）。
- 不改数据库 schema；不改导出格式。
- 不翻译、不改写上游 skill 正文。

## 3. 原样整理 v3

### 3.1 契约

**输入**：`rawTranscript`
**输出**：纯正文（无标题、无标记）

| 类别 | 规则 |
|---|---|
| 必须原样保留 | 人物、地点、事件、事件顺序、因果、结局；数字/日期/时间/数量；专名；颜色/方位；不确定词（好像/大概/可能/记不清/说不准）；引语的意思 |
| 必须删除 | 语气词（呃/嗯/唔/唉/哎/诶）、填充词（就是说/那个·作填充/你知道吧/怎么说呢/反正就是）、元话语（我思考一下/让我想想/就是什么呢/我在想）、连续重复、无意义停顿、输入垃圾 |
| 允许改写 | 合并碎句；压缩重复叙述；调整语序；把口误导致的不成句改顺（不补内容） |
| 禁止 | 新增原文没有的事实、人物、地点、因果、解释、心理补写、比喻性扩写 |

**长度**：输出内容字数 / 输入内容字数 ∈ [0.50, 0.85]，目标 0.60–0.75。

### 3.2 提示词文件

`prompts/faithful.v3.md`，结构：

1. 角色：记录员，不是作者。
2. 事实清单（不可动）。
3. 可删清单（6 类，含元话语与隔开的重复）。
4. 可改清单（合并/压缩/调序，正反例）。
5. 压缩目标与改前改后示例。
6. 禁止清单（≤10 条）。
7. 自检（≤10 条）。

`PromptSpecs.FAITHFUL` 指向 v3；旧 v2/v2.1 文件保留可回滚。

### 3.3 闸门（faithful v3）

| 闸门 | 判据 | 失败处理 |
|---|---|---|
| **F1 事实锚点** | 输入中提取的数字/日期/时间/数量/颜色/方位/疑似专名集合，必须在输出中**全部出现**（按集合，不按次数） | 重试一次，违规清单进 prompt |
| **F2 压缩率** | `contentChars(out)/contentChars(in)` ∈ [0.50, 0.85] | 过高→要求删口水重复；过低→要求补回事实 |
| **F3 口水清零** | 引号外不得出现：语气词单字（呃/嗯/唔/唉/哎/诶）；元话语短语；连续重复（≥2 字，白名单：人人/常常/慢慢/渐渐/刚刚/好好/看看/想想/试试/说说）；相邻整句重复 | 直接判红，重试 |
| **G4** | 不得新增跨场景因果词（沿用 v2） | 沿用 |
| **G5** | 不确定词保留率 100%（沿用 v2） | 沿用 |

移除：G1（新增实词）、G2（≤110%）、G3（2-gram ≥95%）、G6（改字 ≤2）对 faithful 的绑定。

revise 链保留 **G1–G5**；**G6 不再挂在任何链上**——revise 是整体改写，允许换字，
G6 会把正常改动判红（实现时用 3 处换字实测确认）。枚举与旧向量保留，回滚 v2 时接回即可。
理由：它们与「重写措辞」互斥。

**重试策略**（沿用现有 T 链语义）：
- T0：正常整理（temp 0.1，无违规清单）；
- T1：带 T0 违规清单重试一次；
- T2：只做标点（输出不得增删实词，仅补标点/断句）；
- T3：不调模型，原样回退（只加标点）。
任何一档通过即落库；T0/T1 由 F1–F3 判定，T2 由「实词零变化」判定（输出内容用字必须是输入的子序列），T3 必然通过但不计入「整理成功」，UI 标注「已回退原文」。

### 3.4 思考档位

- 新设置键：`dk_generation_faithful_thinking`（与小说化思考 `dk_generation_thinking` 一样是应用级、不按供应商分），取值 `OFF/LOW/HIGH/MAX`，默认 `LOW`。
- 请求体：思考开启时不发 `temperature`；关闭时 `temperature=0.1`（现状）。
- UI：设置 → 模型服务 → 单家详情 → 「原样整理思考」四枚胶囊。

## 4. 小说化 v3

### 4.1 契约

**输入**：原样稿 + 可选用户想法
**输出**：JSON `{title, body, notes, mood}`

| 允许 | 要求 |
|---|---|
| 删事件、换结局、改人物关系、合并人物、新建世界观、换视角/时态、加功能性配角 | 均允许 |
| 舍弃原样稿大部分内容 | 允许 |

**必须保留的梦 DNA**（写进 `notes`，可检查）：
1. 至少 1 个核心意象/场景（原文出现过）；
2. 情绪的真相（原文情绪指向）；
3. 一个从梦里长出来的异常前提。

**故事引擎**（三段式规划阶段的硬输出）：
- 前提：主角想要什么 / 什么挡住 / 代价；
- 主题：`{价值} {胜/败}，因为 {原因}` + 反前提；
- 场景表：3–5 场，每场 `goal/conflict/outcome`；关键处加 `reaction/dilemma/decision`；
- 结尾必须改变某样东西（关系/认知/代价）。

### 4.2 三段式流水线

| 阶段 | 输入 | 注入参考（英文原件） | 输出 | 校验 |
|---|---|---|---|---|
| **PLAN** | 原样稿、用户想法 | premise-workshop、controlling-idea、short-story-form | 规划 JSON（字段见 §4.2.1） | schema：字段齐全、场景 3–5、主题句含「因为」 |
| **DRAFT** | 规划 JSON、原样稿、用户想法 | scene-sequel、openings、dialogue-subtext、prose-checks、anti-slop | 小说 JSON | N1 + N2 |
| **POLISH** | DRAFT 的 body、规划 | line-edit-checklist、prose-checks、anti-slop | 小说 JSON（修订） | N1 + N2 + 长度变化 ≤±10% |

- 任一步 schema/N1/N2 失败：该步重试 1 次；POLISH 后仍红 → 整体失败并回显原因（不静默产出）。
- PLAN 不进数据库正文；`generation_job` 每阶段一行（stage=`PLAN`/`DRAFT`/`POLISH`）。
- 三段之间可取消；取消后不落库。

### 4.2.1 规划 JSON 字段

```json
{
  "premise": "一句话前提",
  "want": "主角想要什么",
  "obstacle": "什么挡住",
  "cost": "代价",
  "controllingIdea": "{价值}{胜/败}，因为{原因}",
  "counterPremise": "反前提",
  "pov": "FIRST|THIRD",
  "targetLength": 1500,
  "scenes": [
    {"goal": "…", "conflict": "…", "outcome": "…",
     "sequel": {"reaction": "…", "dilemma": "…", "decision": "…"}}
  ],
  "endingChange": "结尾改变了什么",
  "coreImages": ["原文里的核心意象"],
  "emotionalTruth": "原文情绪指向"
}
```

校验：字段齐全且非空；`scenes` 3–5；`targetLength` ∈ [800, 5000]；`controllingIdea` 含「因为」；`coreImages` 至少 1 条且每条能在原样稿中找到（精确子串）。

### 4.3 闸门（novel v3）

| 闸门 | 判据 |
|---|---|
| **N1 结构** | 合法 JSON；`title` 4–14 字；`body` 800–5000 内容字、≥3 段；`notes` 3–6 条，每条 `type ∈ {借用,舍弃,新造,主题}`、`detail` 1–60 字；`mood` 1–6 字 |
| **N2 文风** | ① A7 禁词 = 0（沿用）；② 解码句（象征着/意味着/其实是在说/代表着/暗示着）= 0；③ 套话清单（不仅仅…更是…、值得注意、在当今…的时代、总而言之、让我们拭目以待、为…奠定基础、充满活力、令人叹为观止、专家认为）= 0；④ filter words（看见/听到/感觉到/意识到/发现/觉得/注意到）≤10 次/千字（对白外）；⑤「地」副词 ≤12 次/千字；⑥ 说书式标签（吼道/冷哼道/嗤笑道/怒道/沉声道/笑道）≤2 次/篇；⑦ 破折号 ≤3 处/篇 |
| **N3 完整度（仅提示，不进 failed 集合）** | ≥3 段；至少一处对白或动作段；句长标准差 ≥5（20 句以上时） |

删除：G1/G2/G3/G5 在 novel 模式的绑定（事实闸门与自由改编互斥）。

### 4.4 创作手记

`novel_versions.changeLogJson`：

- 旧（v2 及以前）：`[{type:"补写",detail,quote}]` → UI「补写 N 处」；
- 新（v3）：`[{type:"借用|舍弃|新造|主题", detail}]`（无 `quote`）→ UI「创作手记 N 条」。

读取规则：条目含 `quote` 字段按旧版渲染；否则按新版。**不迁移数据库**。

## 5. Skill 资产

- 位置：`android/app/src/main/assets/skills/story-skills/**`（131 个 md，797 KB，MIT）。
- `assets/skills/MANIFEST.json`：`{source, commit, files:[{path, sha256, license:"MIT", stages:[...]}]}`。

## 11. 风险

| 风险 | 缓解 |
|---|---|
| F2/F3 误伤导致重试变多 | 4 条样本先校准；白名单；阈值集中在常量便于调 |
| 三段式耗时 1–3 分钟 | 阶段可见、可取消、失败指明阶段 |
| 注入参考过多稀释指令 | 每阶段字符上限；清单顺序固定 |
| 模型把「自由改编」写成与原梦无关 | DNA 三条进规划与自检；notes 必须声明 |
| 旧版本清单渲染错 | 按 `quote` 字段分流 + 兼容测试 |
| 成本上升 | UI 显示实际累计；用户可调低思考档 |
