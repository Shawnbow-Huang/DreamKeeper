## 0. 一句话

**趁梦还在的时候把它抓住。** 睡醒抬手就说，说完就有两份东西：一份一个字都没改的原样记录，一份读得通的小说。

---

## 1. 背景与目标

朋友有记录梦境的习惯；我高中做过一个剧情反转精彩、但醒来没多久就忘了的梦，很可惜。

所以这个 App 要解决的不是"写日记"，而是**记忆在 90 秒内挥发**这个生理事实：

- **摩擦必须趋近于零**：从睁眼到开口，三步以内。
- **不许篡改**：梦最珍贵的是它"不讲道理"的部分，任何"顺手帮你捋顺"的处理都是破坏。
- **但也要好看**：原样稿是档案，小说稿是作品，两者并存不互相覆盖。

## 2. 范围

### 第一版要做

| 能力 | 说明 |
|---|---|
| 语音快录 | 醒来即录，锁屏可达，声音落本机 |
| 本地转写 | 手机端 STT，文字不外发（除非用户改选全云） |
| 原样记录 | 只断句、加标点、分段，**不增删实词** |
| 小说化润色 | 保留核心情节/意象/情绪，重组成有起承转合的短篇 |
| 保存与查看 | 日历主屏 + 列表 + 详情 |
| 二次编辑 | 两稿都可改，改动留痕 |
| 检索 | 全文搜索（必须有）+ 标签 |
| 标签 | 自动生成、可改可删可合并 |
| 设置 | 自填 API Key、选模型、选转写引擎 |

### 第一版不做（但留位置）

- 梦 → 视频（预留 `MediaAsset` 表与详情页素材区）
- 梦 → 插画（同上，同一张表）
- 云同步、账号体系、多端
- iOS
- 分享/导出成图片

## 3. 八条已定决策

| # | 问题 | 决策 | 关键约束 |
|---|---|---|---|
| 1 | 醒来怎么进录音 | **首页大红钮 + 锁屏快捷入口，共用同一条录音链路** | 双入口不能是两套代码 |
| 2 | 原样记录做到多原样 | **只断句分段**（加标点、分段、留白；口癖保留） | 字符级 diff 校验，只允许插入标点/空白、删纯口癖；违规自动回退原文 |
| 3 | 小说化放开到什么程度 | **放开写**（可为节奏补场景、心理、对白，事件骨架不变） | 原样稿永远保留；小说稿标注"有演绎"；附改动清单 |
| 4 | 松手后 30 秒 | **追问"还有吗"**（30 秒补录窗口，并进同一条梦） | 极暗界面、不发声、只轻震一次、超时自动收起 |
| 5 | 详情页两稿怎么共处 | **切换标签** | tab 写「小说化 · 补写 6 处」，点小字进逐段对照；原始录音永远挂一条 |
| 6 | 标签从哪来 | **全自动** | 可改可删可合并；情绪标签必须有原话依据；定期合并同义 |
| 7 | 数据链路 | **半本地**（手机转写，只把文字发给用户自己的 Key） | 音频永不出机；Key 进 Keystore；发送前可见；断网排队 |
| 8 | 首页形态 | **日历为主屏**，其余形态降为次级视图 | 卡片流 / 时间轴 / 搜索都要在，只是不抢主屏 |

### 决策 8 的落地（四种形态如何共存）

- **日历**（默认首屏）：月视图，有梦的日子点红点，点格子看当天。
- **搜索**：固定在日历顶部一个框，任何时候可搜全文。
- **全部**：底部第二个 tab，默认时间轴，可切卡片流（记住选择）。
- **当日列表**：点日历格子进入，用卡片流。

> 结论：四种都要，但只有一种是"打开就看见"。其余三种各自待在自己该在的位置。

## 4. 核心模型：一条梦有四个层次

这是整个设计最关键的一处判断——**两种模式不是两篇文章，是同一份素材的两个视图**。

```
DreamRecord
├── rawAudio       录音文件（本机私有目录，永不上传）
├── rawTranscript  STT 原始文字（不可变，第一手证据）
├── faithfulText   原样稿（由 rawTranscript 派生，受 diff 约束）
├── novelText      小说稿（当前选中的版本；历史版本并存、可回退，带改动清单）
└── mediaAssets    预留：插画 / 视频
```

原文永远不可变。后面三层都能重算、能多版本、能回退——因为**只有声音是一次性的**。

## 5. 数据模型

```kotlin
DreamRecord(
  id: UUID,
  ownerId: String,          // 默认 "local"；界面不暴露切换
  dreamDate: LocalDate,     // 梦属于哪一晚（可手动改，与 createdAt 区分）
  createdAt: Long,          // 实际录入时间（epoch 毫秒）
  title: String?,           // 可空，模型可建议
  rawAudioPath: String?,
  rawAudioMs: Long?,
  rawTranscript: String,    // 不可变（转写没出来时为空串，由 transcriptStatus 解释，不用空串当哨兵）
  transcriptStatus: String, // PENDING | OK | FAILED，默认 OK
  faithfulText: String?,    // 原样稿
  faithfulEditedByUser: Boolean,
  novelText: String?,       // 小说稿（当前选中的版本）
  novelVersion: Int,        // 每次生成或改稿 +1
  novelSelectedVersion: Int?, // 用户挑中的版本号；null = 未挑（列表与导出用最新版）
  novelChangeLog: String?,  // JSON：模型自列的补写清单
  novelEditedByUser: Boolean,
  mood: String?,            // 单一主情绪，可选
  isDraft: Boolean,         // 录音完成但未生成/未确认
  deletedAt: Long?,         // 软删除，回收站 30 天（epoch 毫秒）
  updatedAt: Long           // epoch 毫秒
)

Tag(id, name, kind, source, evidenceText?)
  kind   = PERSON | PLACE | OBJECT | ACTION | EMOTION | OTHER
  source = AUTO | USER
  evidenceText = 用户原话片段（EMOTION 必填，用于"不许机器归纳感受"）

DreamTag(dreamId, tagId, confidence?)

MediaAsset(id, dreamId, type, path, prompt, model, status, createdAt)
  type = IMAGE | VIDEO   // v1 无写入方，仅建表 + 详情页占位

// 下面四张表 Plan 1 不建：建表与 DAO 归 Plan 3，届时 v1→v2 有 schema 基线可验。
// 字段保留在此作为 Plan 3 的建表依据，不是「已经建好的表」。
GenerationJob(
  id, dreamId, kind,      // FAITHFUL_CLEANUP | NOVEL | NOVEL_REVISE | TAGGING | TITLE
  status,                 // PENDING | RUNNING | OK | FAILED | CANCELLED
  provider, model, promptId, promptVersion, promptHash,
  tokensIn, tokensOut, error, createdAt   // createdAt：epoch 毫秒
)

// 小说化的多版本：多版本并存，用户挑一个当最终稿（§6.3）
NovelVersion(
  id, dreamId, version,   // 版本号从 1 递增
  text,                   // 该版全文（正文只存这里，别处只存指针）
  changeLogJson,          // [{type, detail, quote}]，与 §6.2 同构
  origin,                 // GENERATE | REVISE
  promptId, promptVersion, promptHash,
  createdAt
)

// 对话改稿的消息流（§6.3）。assistant 消息只存"这一轮干了什么"的一句话摘要，
// 正文永远在 NovelVersion 里，避免同一段文字存两份。
NovelMessage(
  id, dreamId, role,      // USER | ASSISTANT
  content,
  versionId,              // 产出新版本时指向该版本；反问/拒绝时为 null
  createdAt
)

// 成本计量（§9）：一次调用一行，金额用整数微元，避免浮点误差
LlmCall(
  id, dreamId, kind,      // FAITHFUL | NOVEL | REVISE | TAGGING | TITLE
  model, reasoningEffort, // OFF | LOW | HIGH | MAX
  cacheHitTokens, cacheMissTokens, outputTokens,
  isPeak,                 // 是否落在高峰时段（北京时间工作日 9–12、14–18）
  priceSnapshotJson,      // 当时单价快照：调价后历史账目不能跟着变
  costMicroYuan,          // 整数微元（1 元 = 1_000_000）
  latencyMs, error, createdAt
)

AppSettings(provider, baseUrl, model, reasoningEffort, apiKeyAlias, sttEngine, nightBehavior, ...)
```

设计说明：

- `dreamDate` 与 `createdAt` 分开：梦属于那一晚，但你可能中午才补记。
- `transcriptStatus`：**开录即 `PENDING`，转写成功 `OK`，失败 `FAILED`**。断网首跑、本机没有中文离线包、API 26–30 没有 on-device 识别时，「录音已落盘、文字还没出来」是必然出现的中间态；`rawTranscript` 保持非空（字段约束），空串由状态解释——**不能用空串当哨兵**，那会和"真的录到一段静音"混成一件事。
- `faithfulEditedByUser` / `novelEditedByUser`：用户改过之后，重生成必须**先确认覆盖**，默认另存新版本。
- 软删除 + 回收站：误删一条梦是灾难级事故。
- `ownerId` 只留字段不建 UI（见决策表附注）。
- **时间戳一律 `Long`（epoch 毫秒）**：`createdAt` / `updatedAt` / `deletedAt` 以及将来的生成、素材时间戳都不用 `Instant`——省一层 `TypeConverter`，SQLite 里可直接比较与排序。
- **生成相关的四张表（`generation_jobs` / `novel_versions` / `novel_messages` / `llm_calls`）不在 Plan 1 建**：连同 DAO 归 **Plan 3**，届时 v1→v2 有真实 schema 基线可验；Plan 1 只落迁移基建（`exportSchema` + 基线 schema）。
- **提示词不建表**：唯一真源是 `prompts/` 下的文件，版本 = 文件名 + 内容 sha256（见 §7.1），数据库只存 `promptId` / `promptVersion` / `promptHash` 三个指针。
- **金额用整数微元**（`costMicroYuan`），不用 `Double`：0.1 + 0.2 在浮点里不等于 0.3，账单不能这么算。
- **单价快照写进每次调用**：官方调价后，历史账目不能跟着变。

## 6. 三条生成链路

### 6.1 原样记录（理顺：调模型，但不许创作）

**模式一永远是「STT 转写 → 大模型理顺」**，不再有"零 LLM 默认路径"。理由：录音里的口水和断句必须有人替他理顺，否则那不是记录，是语音备忘。

**它只做四类事**：

1. 删口头噪声：语气词（呃 / 啊 / 那个 / 就是说 / 然后然后）、纯重复、说一半改口的前件、无意义停顿；
2. 断句与分段：补标点、按语义分段、保留原有的空行与节奏；
3. 顺着场景硬切词分段：「后来切换到了教室里」「画面一转」「画面再一转」——这些词**必须原样保留**，它们是梦里换场的唯一线索；
4. 清理输入垃圾：`[em]e400636[/em]` 这类表情残留、多余空格、转写乱码——改动记一条「清理格式」。

**它禁止做的事（一条都不许）**：

- 补因果（"因为我怕，所以…"）、解释荒诞（"也许是睡姿造成的"）、补描写、补心理推测；
- 改语序、换用词、把别扭的句子改成通顺的句子 —— **别扭是梦的一部分**；
- 合并、删减、移动任何事件，或调整先后顺序；
- 删括号里的自我吐槽（"（我好像并没有这么做，有点傻orz）"）与旁白（"（可能因为是我的梦所以上帝视角哈哈哈哈）"）——这是用户原话的一部分；
- 给人物命名、给场景命名、加小标题。

改错别字要克制：只在明显是听写错误时改（「嚯」→「喝」），并记一条「修字」。

**失败处理链（三级，必须实现）**：

1. 第一次：温度 0.1 正常理顺 → 跑 `scripts/check-faithful.py` 五个闸门；
2. 不过 → 第二次：温度降到 **0.0**，把**具体违规项**写回提示词（"上一版你新增了『像被什么托着』、把『按不到一楼』改成『按不到楼层键』，这次一条都不许出现"）；
3. 还不过 → **保守版**：只做标点与分段、一个字不改，页面标一行「这段系统退回了保守处理」；
4. 连保守版都产不出来 → 直接展示 `rawTranscript` 原文，并提示「这条建议你手动改一下」。

原始转写永远在"原样"页留一个可点开的入口（「看原始转写」），所以降级不会丢东西。

**为什么不用字符 diff 做死判定**：人自己校对时也会修笔误、也会把「我"嚯"了一身」改成「我喝了一声」。闸门只盯**专名 / 数量 / 颜色 / 方位**这类硬指标与覆盖率，不做逐字符比死——过严会把正当的理顺判成违规，过松则等于没闸门。

### 6.2 小说化润色

输入：`faithfulText`（理顺后的流水账；为空时回退 `rawTranscript`）+ 可选历史风格样本。理由是用户原话：小说化要「以流水账为底本补因果、世界观、描写、人称」，底本越干净，演绎越可控。
输出：JSON `{ title, body, changeLog: [{type, detail, quote}], mood }`。

`changeLog` 每条的 `quote` **必须是原样稿里的精确子串，4–40 字**；界面用 `rawTranscript.indexOf(quote)` 定位并高亮**首个**匹配，**不引入字符偏移**（偏移会在原样稿被编辑后全部错位，而子串是自校验的：找不到就不高亮，而不是高亮错行）。tab 标题里的 N = `changeLog` **数组长度**。

因为选的是「放开写」，安全网不放在生成端，放在**可见性**上：

1. 原样稿永远在旁边，不覆盖、不隐藏。
2. 小说稿页头标注「有演绎」。
3. 每条小说稿附**改动清单**：模型自己列出新增的人物、对白、情节、感官细节。
4. tab 标题写「小说化 · 补写 6 处」，点开小字进逐段对照（按 `quote` 定位，模型补的部分高亮）。**「补写 N 处」这几个字是 UI 契约**——`novelTabLabel` 靠正则 `补写\s*(\d+)\s*处` 决定是否显示逐段对照入口，改成「改写」「润色」会让入口静默消失。
5. 不满意 → 一键重生成，或直接用 §6.3 的对话改稿。

### 6.3 对话改稿（小说化之后）

小说稿下面常驻一条输入框：「哪里不对，说说看」。用户说一句，模型改一版；不满意再说，再改。

**三条硬原则**：

1. **最小改动，不重写全文**。改稿输出与旧稿的**正文字数比（不计标点空白）**必须 ≤ 115%，否则一次"改个结尾"会把全文风格洗掉。
2. **歧义先问，不猜着改**。用户说「结尾不好」时，模型要么只改结尾，要么返回一句反问（「是说太说教，还是整段不要？」）并且**这一轮不产出新版本**。猜错一次，后面会越改越远。
3. **每版必留、必可撤回**。每次改稿写一行 `NovelVersion`，旧版永久保留；界面上是版本线（`v2 · 按你说的删了那两段描写 · 改动 3 处`），点「撤回」回上一版。

**继承小说化的全部契约**：不许借改稿新增人物关系、换结局、新增关键事件、解释隐喻；改完同样跑 G1–G5 与 21 条 AI 味规则；不过就按 §6.1 的同一条失败链处理（温度 0 重试一次并附违规清单 → 仍不过则**保留旧版**并说明哪条没过）。

**多版本并存 + 挑选最终稿**：`novel_versions` 保留全部版本；`dreams.novelSelectedVersion` 记住用户挑中的那一版（`null` = 未挑）。列表、导出、分享都用挑中的那版；没挑则用最新版。标题栏显示「当前 v2 · 已选中」。

**快捷按钮**（手机上打长句太累）：太文绉绉 / 细节太多 / 结尾太说教 / 人称不对 / 多点环境 / 少点形容 —— 点一下填入输入框，可再编辑。

## 7. 提示词工程

### 7.1 结构：四段式，存文件不存代码

```
prompts/
├── faithful.v2.md        理顺：角色 → 可删白名单 → 禁改清单 → 输出格式
├── novel.v2.md           小说化：角色 → 事实契约 → 风格契约(A1–A21) → JSON
├── novel_revise.v1.md    对话改稿：最小改动 + 歧义先问 + 继承事实契约
├── tagging.v1.md         （Plan 3）
└── title.v1.md           （Plan 3）
```

- 进 `assets/prompts/`，带版本号；改动即新增版本，旧版本保留。
- **文件是唯一真源**：版本 = 文件名里的版本号 + 文件内容 sha256；数据库只存版本指针（`promptId` / `promptVersion` / `promptHash`），**不存提示词正文**（`prompt_versions` 表归 Plan 3，见 §5）。改提示词就是一次 git diff，不是一次 SQL。
- **禁止把提示词硬编码在 Kotlin 字符串里**（改不了、测不了、回滚不了）。
- 参数：见 §9 的档位表（`faithful` 0.1、重试降到 0.0；`novel` 0.9 + 思考 high；`revise` 0.3；`tagging` / `title` 0.2）。
- 版本策略：`v1.x` 内允许「只加键、不改既有键」的增量（如加 `quote`），破坏既有键才升 v2；旧版本文件永久保留，`prompts/CHANGELOG.md` 记 sha256_8。

### 7.2 去 AI 味：当作工程问题，不当作审美问题

四层机制：

**① 契约层**
- 原样记录（理顺）：**允许删口水、补标点、分段、清理垃圾字符**，除此以外禁止任何创作——连"补一个合理的词"都不行。契约与三级失败链见 §6.1。
- 小说化：**允许**重组顺序、补场景描写、补心理活动、补对话；**禁止**新增人物关系、新增或替换结局、新增关键事件、解释梦的隐喻、把跳跃处"讲圆"。
  判定口径：把 AI 补的部分全部删掉，读者仍能认出"这就是那个梦"。

**② 黑名单（可检查）**

禁用词/句式：三段式排比、「不是……而是……」、「这一刻我突然明白」、「仿佛整个世界都……」、「不禁」、「涌上心头」、「心中五味杂陈」、结尾升华段、破折号滥用、每段等长。

**③ 正例（反向要求）**
- 保留梦的不确定性：「好像」「记不清了」「突然就变成」「后来不知道怎么」。
- 不给隐喻做解释——梦里的电梯就是电梯，不写"象征着……"。
- 句长必须参差；允许突兀的转折和断裂的因果。

**④ 自检重写 + 离线审 + 三层评价**

- 初稿 → 自检提示词（"逐条检查上述黑名单，列出违规并重写"）→ 终稿。
- 离线可用 `humanizer-zh` / `writing-anti-ai` skill 复审。

**评价体系不依赖"标准答案文本"。** 用户提供的两条亲笔例子只作两种用途——**下限尺子**（新稿"读得通"不许比它们更差）与**口味参照**（信息密度、忌口）——**绝不作对照答案**：它们本身有漏、有含糊、有笔误，当正确答案会把"照抄人的疏漏"评成合格，也会把"模型做得更好"评成扣分。

1. **规则闸门（可执行、硬红）**，由 `scripts/check-faithful.py` 实现，任一项红即本轮不通过：
   - G1 新增专名 / 数量 / 颜色 / 方位词出现次数 = 0；
   - G2 正文长度比（输出/输入的字数，**不计标点与空白**）≤ 110%；标点只能插入，数进长度比等于禁止合法操作
   - G3 原文关键名词与动词覆盖率 ≥ 95%；
   - G4 跨场景因果连接词（于是/因此/所以/正因为/导致）跨段出现 = 0；
   - G5 不确定词（好像/记不清/大概/似乎/可能）保留率 = 100%。
2. **盲评偏好（不做绝对分）**：同一篇梦出两版（保守版 / 放得开版），遮掉版本标签，只问"更喜欢哪个、哪句过了"，记选择与理由。没有标准答案时绝对分不可复现，偏好是唯一稳定信号。
3. **下限基线**：只在"读不读得通"上与用户例子比，判据是"不更差"，不是"像不像它"。

计数型硬指标（**编造次数**、**原样整理违规次数**）保留、**目标 0**、各自一票否决；分母是"本轮实际跑了几条"，不再绑定 20 条样本。真实样本由用户随手提供，样本不足时不许下结论，但不许伪造，也不许因此停住开发。

5. **分层审稿（参照社区 skill 的做法）**：改稿不自检"再读一遍"，而是按层定位——结构（事件顺序有没有被悄悄动过）、句法（声部是否一致、有没有三段一样长）、校对（错字、标点）。每层只修这一层的问题，避免一次大改把结构问题与错别字搅在一起。
   另加一步「读者复述测试」：把 AI 补的部分删掉后，只看剩下的事件能否复述出骨架——能，才算没把梦讲丢；不能，说明这次演绎伤到了本体。



### 7.3 风格画像（最强的一招，v1 可后置）

累积 20 条以上记录后，从用户自己的文字里抽 style profile（常用词、句长分布、口癖、叙述视角），注入后续生成。这比任何"去 AI 味提示词"都有效，因为**它抄的是你本人**。

## 8. 语音链路

```
点击 → 前台服务启动 → 录音（AudioRecord/MediaRecorder）
     → 落盘 app 私有目录（不留存储权限）
     → 并行：本地 STT 流式出字
松手 → 停止 → 写 rawTranscript
     → 30 秒"还有吗"窗口（可追加，拼进同一条）
     → 超时 → 收起、熄屏、后台跑标签/小说化
```

- **权限**：仅 `RECORD_AUDIO`（+ 通知权限）。不申请存储权限。
- **锁屏可达**：Android 没有 iOS 那种锁屏小组件，实际可用的是
  ① 快捷设置磁贴（TileService）
  ② 常驻通知上的录音按钮
  ③ 桌面/Long-press 快捷方式
  三者指向同一个 Activity。
- **不丢录音**：前台服务 + 写文件即时 flush + 启动时扫描孤儿文件恢复（细则见 §8.1）。
- **转写引擎**：优先系统 on-device STT；不可用时按设置退回云端（用自己的 Key）。引擎可换，文字可重转——因为音频留着。

### 8.1 音频存储契约（Plan 2 的实现依据，不得自行改动）

1. **一条梦 = 一个连续文件**。从按下红钮开始，一直录到追问窗口超时（包括中间静音的那段时间）；补录**不换文件、不转码**，只是把新的字节追加到同一个文件末尾。
2. **路径固定为 `files/audio/<dreamId>.wav`**（app 私有目录，不需要任何存储权限）。`dreamId` 是 UUID，**在开始录音之前就生成**——先有 id，才有落盘路径；反过来（先录、录完再分配 id）一旦进程被杀，文件就成了无名孤儿。
3. **编码：PCM 16kHz 单声道 WAV**（约 1.92 MB/分钟）。理由只有一个但足够硬：**进程被杀时文件仍然是可播放的完整 WAV**——WAV 头在开录时就写好、之后只是追加 PCM 数据，最坏情况是时长少一点。`MediaRecorder` 的 M4A 在进程被杀时 `moov` box 常常没写，文件根本打不开，而"声音只有一次"这件事经不起这种损失。体积换可靠性，这是已经拍板的取舍。
   - **头的长度字段怎么填**：开录时 `RIFF` 的 chunk size 与 `data` 的 size 都写 `0xFFFFFFFF` 占位（此时还不知道会录多久，也不能每次都 seek 回去改）。**松手时回填**（停止 `AudioRecord` 前后、close 之前，把真实字节数写回那 8 个字节）。
   - 因此"文件头是不是好"的判断标准是**那两个字段等不等于 `0xFFFFFFFF`**，不是"文件存不存在"。占位残留 = 上次没走到松手回填，由启动扫描修复（见第 5 条）。
4. **回收站 30 天内音频文件保留**：删除是软删除（`deletedAt`），音频**不删**——用户后悔了要能连声音一起恢复。物理清除（超过 30 天或用户点"彻底删除"）时，**数据库行与音频文件成对删除**：先删文件再删行，或先删行再删文件都行，但必须是同一次操作里完成，不许只删一边。
5. **启动时扫描 `files/audio/`**：对每个文件按文件名解析出 `dreamId`，查库——
   - 有对应行：**正常，但仍要校验并修复 WAV 头**——`RIFF`/`data` 的长度字段在开录时写的是 `0xFFFFFFFF` 占位（见第 3 条），若上次没走到"松手回填"（进程被杀、电量为 0），这里必须按真实字节数回填；头校验通过才什么都不做。
   - 没有对应行（写入过程中崩溃、或数据库被清过）：**能恢复就恢复**（按文件名 id 把音频挂回一条草稿记录，`transcriptStatus = PENDING`，让用户可以重转或删除），恢复不了才清理；
   - 反向的孤儿（有 `rawAudioPath` 但文件不在）：把 `rawAudioPath` 置空、`transcriptStatus = FAILED`，不要留一个指向不存在文件的重试入口。
6. **焦点被抢时不许断时间轴**（来电、闹钟、其它 App 抢音频焦点）：这些时间段里 `AudioRecord` 读不到 PCM，实现必须**补等长零字节**进文件——时间轴不断，这样"第 12 分钟说的话"永远在文件的第 12 分钟位置，补录追加、播放进度、逐段对照的定位都不需要重新算偏移。**代价是静音段占体积，这是刻意接受的**。
   - `rawAudioMs` 的定义固定为 `(文件字节数 - 44) / 32`（44 = WAV 头长度；32 = 16kHz × 1ch × 2 bytes/样本 ÷ 1000ms）。即**文件真实时长，含补的零**。
   - **不许用墙钟算时长**：墙钟会把"接电话的那 2 分钟"算进去、而文件里没有对应字节，播放到末尾就露馅；两者不一致时以文件为准。

## 9. LLM 接入层

**只接 DeepSeek 官方**（用户决策：暂时单厂商）。仍然保留一层薄抽象 `LlmClient.chat(messages, schema) -> JsonObject`，将来加第二家 = 加一个 adapter 文件，不动调用方。

- 端点：`POST https://api.deepseek.com/chat/completions`，OpenAI 兼容格式。
- 模型：默认 **`deepseek-flash`**（用户决策：全程默认 flash，理由是目前 flash 各方面超过 v4-pro 且更便宜）；`deepseek-v4-pro` 仍列在下拉里作备选，不推荐。
- 思考控制：`thinking: {type: enabled|disabled}` + `reasoning_effort: low|high|max`。`medium` 等会被服务端映射成 high，是假中间档，界面里不提供。
- **思考开着时 `temperature` / `presence_penalty` / `frequency_penalty` 被服务端忽略**（不报错，只是不生效）——设置页必须写这句话，否则用户以为调温没反应。
- 默认档位（设置页改全局，详情页 48dp 小按钮改单条）：

  | 用途 | 模型 | 思考 | 温度 |
  |---|---|---|---|
  | 理顺（§6.1） | flash | 关 | 0.1；重试降到 0.0 |
  | 小说化（§6.2） | flash | **开 high**（可调 max） | 0.9（仅思考关闭时生效） |
  | 对话改稿（§6.3） | flash | 开 low | 0.3 |
  | 标签 / 标题（后台） | flash | 关 | 0.2 |

- 结构化输出：`response_format: {type: "json_object"}` + 提示词里给 JSON 样例；解析失败按一次失败计入重试链，**不许静默用原文顶替**。
- 失败策略：网络 / 5xx / 429 走指数退避重试 3 次 → 标记 `FAILED` 并保留重试入口。**绝不静默丢弃生成请求。**
- 成本：每次调用写一行 `llm_calls`（§5），含缓存命中/未命中 token、输出 token、是否高峰、**当时单价快照**、整数微元金额。价格做成一张表 + 一处 `updatedAt`，官方改价只改表不改逻辑。峰谷口径：北京时间工作日 09:00–12:00、14:00–18:00 为高峰，其余为低谷（参考 `dsh-cost-meter` 的做法）。
- 成本可见：详情页顶部一行「这条花了 ≈0.03 元」；设置页「用量」按天 / 按模型汇总，可一键清空。
- **费用由用户自付**：App 不转售、不代理、不加价；设置页首次填 Key 时明说"消耗的是你自己账号的额度"。Key 存 Keystore，不进日志、不进备份、不打进截图证据。

## 10. 隐私与安全

写死的四条：

1. **原始音频永不离开本机。** 任何版本不得上传音频（除非用户明确改选全云）。
2. **API Key 存 Android Keystore 加密存储**，不进日志、不进备份、不进崩溃上报。
3. **发送前可见**：首次调用某 provider 前，把将要发送的内容显示给用户看一眼。
4. **断网可用**：录音照录、本地转写照跑、小说化进工作队列等联网。

其他：`android:allowBackup=false`（内容私密，不参与自动备份）；日志默认脱敏（正文只打长度）。

### 13.1 仓库结构

```
DreamKeeper/
├── android/        Android 工程根（settings.gradle.kts 在这一层）
├── prompts/        提示词（跨平台共享，Android 通过 sourceSets 引入）
├── docs/
│   ├── superpowers/specs/   设计文档
│   └── eval/                评测集：dreams.md / results.md
└── README.md
```

**根目录中立，平台目录只是消费者。** 理由不是整齐，而是：提示词与评测集是真正跨平台的资产——同一句「禁止新增人物关系」换到 iOS 意思不变；评测集的打分标准（先 10 条、逐步攒到 20 条）必须两平台共用，否则两个版本会各自漂移。

**暂不创建 `ios/`**：空目录不被 git 跟踪，`.gitkeep` 只是假装已经在做了。真开始时 `mkdir ios` 是一秒钟的事。

**验证闭环**：Gradle 构建 → `adb install` → uiautomator dump / mobile-mcp 驱动 → **截图**（走 `scripts/capture-screen.ps1`）→ 人眼逐张核对（近白像素闸门走 `scripts/check-near-white.ps1`）→ `adb logcat` 定位（冷启动/崩溃走 `scripts/capture-logcat.ps1 -Runs 3`）。没有自动视觉回归（不搭 Roborazzi / golden 目录），截图就是证据，必须真的打开看。

> **不要用裸 `adb exec-out screencap -p > 文件`**：PowerShell 5.1 会按 UTF-16LE 写重定向，PNG 变成打不开的坏文件（头部 `FF FE FD FF …`），而且报错发生在"打开图片"的时候，看起来像图片工具的问题。脚本内部用 `cmd.exe` 的二进制安全重定向，并做 PNG 魔数 / IHDR / IEND 校验与 SHA256。

## 14. 验收标准

- [ ] 从点亮屏幕到开始录音 ≤ 3 步，≤ 3 秒。
- [ ] 录音过程中接电话/切后台/锁屏，音频不丢。**判据（可执行，不是感觉）**：电话前后说的内容在文件里**连续**（第 N 分钟的话仍在第 N 分钟的位置），通话期间是**等长静音**（补零，见 §8.1-6）；文件是能正常打开、时长与 `rawAudioMs` 一致的 WAV。
- [ ] 原样稿：`scripts/check-faithful.py` 五个闸门全绿（G1 新增专名/数量/颜色/方位 = 0；G2 正文长度比 ≤ 110%（不计标点空白）；G3 关键名词动词覆盖 ≥ 95%；G4 跨场景因果连接词 = 0；G5 不确定词保留 = 100%），且原样整理违规次数 = 0。分母是"本轮实际跑了几条"，不绑定 20 条样本。违反时按 §6.1 的三级失败链处理：最终给用户看到的要么是全绿稿、要么是保守版、要么是原始转写——**不存在"带着违规的稿子"**。
- [ ] 小说化：编造次数 = 0（一票否决）；盲评偏好里用户选"新版"或"持平"；不设 1–5 分绝对评分，也不要求"像人写的 ≥8/10"（没有标准答案时该判据不可复现）。
- [ ] 对话改稿：连续 3 轮修改后 `novel_versions` 至少有 4 个版本且都能切回；每轮正文长度比（不计标点空白）≤ 115%；用户挑中的那一版（`novelSelectedVersion`）在列表与导出里生效；歧义意见至少有一轮走「先问不改」。
