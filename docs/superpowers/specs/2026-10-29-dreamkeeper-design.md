## 0. 一句话

**趁梦还在的时候把它抓住。** 睡醒抬手就说，说完就有两份东西：一份一个字都没改的原样记录，一份读得通的小说。

---

## 1. 背景与目标

朋友有记录梦境的习惯；我高中做过一个剧情反转精彩、但醒来没多久就忘了的梦，很可惜。

所以这个 App 要解决的不是"写日记"，而是**记忆在 90 秒内挥发**这个生理事实：

- **摩擦必须趋近于零**：从睁眼到开口，三步以内。
- **不许篡改**：梦最珍贵的是它"不讲道理"的部分，任何"顺手帮你捋顺"的处理都是破坏。
- **但也要好看**：原样稿是档案，小说稿是作品，两者并存不互相覆盖。

## 2. 范围

### 第一版要做

| 能力 | 说明 |
|---|---|
| 语音快录 | 醒来即录，锁屏可达，声音落本机 |
| 本地转写 | 手机端 STT，文字不外发（除非用户改选全云） |
| 原样记录 | 只断句、加标点、分段，**不增删实词** |
| 小说化润色 | 保留核心情节/意象/情绪，重组成有起承转合的短篇 |
| 保存与查看 | 日历主屏 + 列表 + 详情 |
| 二次编辑 | 两稿都可改，改动留痕 |
| 检索 | 全文搜索（必须有）+ 标签 |
| 标签 | 自动生成、可改可删可合并 |
| 设置 | 自填 API Key、选模型、选转写引擎 |

### 第一版不做（但留位置）

- 梦 → 视频（预留 `MediaAsset` 表与详情页素材区）
- 梦 → 插画（同上，同一张表）
- 云同步、账号体系、多端
- iOS
- 分享/导出成图片

## 3. 八条已定决策

| # | 问题 | 决策 | 关键约束 |
|---|---|---|---|
| 1 | 醒来怎么进录音 | **首页大红钮 + 锁屏快捷入口，共用同一条录音链路** | 双入口不能是两套代码 |
| 2 | 原样记录做到多原样 | **只断句分段**（加标点、分段、留白；口癖保留） | 字符级 diff 校验，只允许插入标点/空白、删纯口癖；违规自动回退原文 |
| 3 | 小说化放开到什么程度 | **放开写**（可为节奏补场景、心理、对白，事件骨架不变） | 原样稿永远保留；小说稿标注"有演绎"；附改动清单 |
| 4 | 松手后 30 秒 | **追问"还有吗"**（30 秒补录窗口，并进同一条梦） | 极暗界面、不发声、只轻震一次、超时自动收起 |
| 5 | 详情页两稿怎么共处 | **切换标签** | tab 写「小说化 · 补写 6 处」，点小字进逐段对照；原始录音永远挂一条 |
| 6 | 标签从哪来 | **全自动** | 可改可删可合并；情绪标签必须有原话依据；定期合并同义 |
| 7 | 数据链路 | **半本地**（手机转写，只把文字发给用户自己的 Key） | 音频永不出机；Key 进 Keystore；发送前可见；断网排队 |
| 8 | 首页形态 | **日历为主屏**，其余形态降为次级视图 | 卡片流 / 时间轴 / 搜索都要在，只是不抢主屏 |

### 决策 8 的落地（四种形态如何共存）

- **日历**（默认首屏）：月视图，有梦的日子点红点，点格子看当天。
- **搜索**：固定在日历顶部一个框，任何时候可搜全文。
- **全部**：底部第二个 tab，默认时间轴，可切卡片流（记住选择）。
- **当日列表**：点日历格子进入，用卡片流。

> 结论：四种都要，但只有一种是"打开就看见"。其余三种各自待在自己该在的位置。

## 4. 核心模型：一条梦有四个层次

这是整个设计最关键的一处判断——**两种模式不是两篇文章，是同一份素材的两个视图**。

```
DreamRecord
├── rawAudio       录音文件（本机私有目录，永不上传）
├── rawTranscript  STT 原始文字（不可变，第一手证据）
├── faithfulText   原样稿（由 rawTranscript 派生，受 diff 约束）
├── novelText      小说稿（可多版本、可重生成，带改动清单）
└── mediaAssets    预留：插画 / 视频
```

原文永远不可变。后面三层都能重算、能多版本、能回退——因为**只有声音是一次性的**。

## 5. 数据模型

```kotlin
DreamRecord(
  id: UUID,
  ownerId: String,          // 默认 "local"；界面不暴露切换
  dreamDate: LocalDate,     // 梦属于哪一晚（可手动改，与 createdAt 区分）
  createdAt: Instant,       // 实际录入时间
  title: String?,           // 可空，模型可建议
  rawAudioPath: String?,
  rawAudioMs: Long?,
  rawTranscript: String,    // 不可变
  faithfulText: String?,    // 原样稿
  faithfulEditedByUser: Boolean,
  novelText: String?,       // 小说稿（当前版本）
  novelVersion: Int,        // 每次生成 +1
  novelChangeLog: String?,  // JSON：模型自列的补写清单
  novelEditedByUser: Boolean,
  mood: String?,            // 单一主情绪，可选
  isDraft: Boolean,         // 录音完成但未生成/未确认
  deletedAt: Instant?,      // 软删除，回收站 30 天
  updatedAt: Instant
)

Tag(id, name, kind, source, evidenceText?)
  kind   = PERSON | PLACE | OBJECT | ACTION | EMOTION | OTHER
  source = AUTO | USER
  evidenceText = 用户原话片段（EMOTION 必填，用于"不许机器归纳感受"）

DreamTag(dreamId, tagId, confidence?)

MediaAsset(id, dreamId, type, path, prompt, model, status, createdAt)
  type = IMAGE | VIDEO   // v1 无写入方，仅建表 + 详情页占位

GenerationJob(
  id, dreamId, kind,      // FAITHFUL_CLEANUP | NOVEL | TAGGING | TITLE | CHANGELOG
  status,                 // PENDING | RUNNING | OK | FAILED | CANCELLED
  provider, model, promptVersion,
  tokensIn, tokensOut, error, createdAt
)

PromptVersion(id, kind, version, body, createdAt)   // 提示词进库，便于 A/B 与回滚

AppSettings(provider, baseUrl, model, apiKeyAlias, sttEngine, nightBehavior, ...)
```

设计说明：

- `dreamDate` 与 `createdAt` 分开：梦属于那一晚，但你可能中午才补记。
- `faithfulEditedByUser` / `novelEditedByUser`：用户改过之后，重生成必须**先确认覆盖**，默认另存新版本。
- 软删除 + 回收站：误删一条梦是灾难级事故。
- `ownerId` 只留字段不建 UI（见决策表附注）。

## 6. 两条生成链路

### 6.1 原样记录（默认零 LLM）

因为选的是「只断句分段」，而系统 STT 本来就带标点，所以**默认路径根本不调大模型**：STT 输出直接作为 `faithfulText`。

只有一种情况调模型：口述极乱、无标点、大量重复时，走 `FAITHFUL_CLEANUP`。

**硬校验（这条是安全底线，必须实现）**：

```
diff(rawTranscript, faithfulText) 的每一个改动必须是：
  ① 插入标点
  ② 插入换行/空白
  ③ 删除纯重复口癖（"就是就是就是" → "就是"）
任何新增实词、任何改写、任何顺序调整 → 判定违规 → 自动回退为 rawTranscript 原文，并记录一次违规
```

评测集里量化「违规次数」，目标 **0**。

### 6.2 小说化润色

输入：`rawTranscript`（不是 faithfulText，避免误差叠加）+ 可选历史风格样本。
输出：JSON `{ title, body, changeLog: [{type, detail}], mood }`。

因为选的是「放开写」，安全网不放在生成端，放在**可见性**上：

1. 原样稿永远在旁边，不覆盖、不隐藏。
2. 小说稿页头标注「有演绎」。
3. 每条小说稿附**改动清单**：模型自己列出新增的人物、对白、情节、感官细节。
4. tab 标题写「小说化 · 补写 6 处」，点开小字进逐段对照（模型补的部分高亮）。
5. 不满意 → 一键重生成，旧版本进历史。

## 7. 提示词工程

### 7.1 结构：四段式，存文件不存代码

```
prompts/
├── novel.v1.md           角色 → 事实契约 → 风格契约 → 输出格式(JSON)
├── faithful_cleanup.v1.md
├── tagging.v1.md
├── title.v1.md
└── changelog.v1.md
```

- 进 `assets/prompts/`，带版本号；改动即新增版本，旧版本保留。
- **禁止把提示词硬编码在 Kotlin 字符串里**（改不了、测不了、回滚不了）。
- 参数：`novel` temperature 0.9、`tagging` 0.2、`cleanup` 0.1。

### 7.2 去 AI 味：当作工程问题，不当作审美问题

四层机制：

**① 契约层**
- 原样记录：**禁止任何创作**，连"补一个合理的词"都不行。
- 小说化：允许重组、允许补感官与场景，**禁止新增事实性内容**（不新增人物关系、不新增结局反转、不解释梦的隐喻）。

**② 黑名单（可检查）**

禁用词/句式：三段式排比、「不是……而是……」、「这一刻我突然明白」、「仿佛整个世界都……」、「不禁」、「涌上心头」、「心中五味杂陈」、结尾升华段、破折号滥用、每段等长。

**③ 正例（反向要求）**
- 保留梦的不确定性：「好像」「记不清了」「突然就变成」「后来不知道怎么」。
- 不给隐喻做解释——梦里的电梯就是电梯，不写"象征着……"。
- 句长必须参差；允许突兀的转折和断裂的因果。

**④ 自检重写 + 离线审 + 人工评测**
- 初稿 → 自检提示词（"逐条检查上述黑名单，列出违规并重写"）→ 终稿。
- 离线可用 `humanizer-zh` / `writing-anti-ai` skill 复审。
- **评测集：`docs/eval/dreams.md` 收录 20 条真实梦境**，每条人工打三项分：
  1. 像不像人写的（1–5）
  2. 有没有丢核心情节（有/无）
  3. 有没有编造事实（有/无）

改任何提示词都必须跑这套评测，结果记 `docs/eval/results.md`。

### 7.3 风格画像（最强的一招，v1 可后置）

累积 20 条以上记录后，从用户自己的文字里抽 style profile（常用词、句长分布、口癖、叙述视角），注入后续生成。这比任何"去 AI 味提示词"都有效，因为**它抄的是你本人**。

## 8. 语音链路

```
点击 → 前台服务启动 → 录音（AudioRecord/MediaRecorder）
     → 落盘 app 私有目录（不留存储权限）
     → 并行：本地 STT 流式出字
松手 → 停止 → 写 rawTranscript
     → 30 秒"还有吗"窗口（可追加，拼进同一条）
     → 超时 → 收起、熄屏、后台跑标签/小说化
```

- **权限**：仅 `RECORD_AUDIO`（+ 通知权限）。不申请存储权限。
- **锁屏可达**：Android 没有 iOS 那种锁屏小组件，实际可用的是
  ① 快捷设置磁贴（TileService）
  ② 常驻通知上的录音按钮
  ③ 桌面/Long-press 快捷方式
  三者指向同一个 Activity。
- **不丢录音**：前台服务 + 写文件即时 flush + 启动时扫描孤儿文件恢复。
- **转写引擎**：优先系统 on-device STT；不可用时按设置退回云端（用自己的 Key）。引擎可换，文字可重转——因为音频留着。

## 9. LLM 接入层

- 统一接口 `LlmClient.chat(messages, schema) -> JsonObject`。
- 适配器：OpenAI 兼容（DeepSeek / Kimi / 通义 / 本地 Ollama）、Anthropic、Gemini。
- 用户填：baseUrl + apiKey + model name。
- 结构化输出优先用 JSON mode / 函数调用；模型不支持时用"输出以 ```json 开头"的降级提示 + 解析兜底。
- 失败策略：指数退避重试 3 次 → 标记 `FAILED` 并保留重试入口。**绝不静默丢弃生成请求。**
- 成本可见：每次生成记录 tokens，设置页显示本月用量（自算，不联网）。

## 10. 隐私与安全

写死的四条：

1. **原始音频永不离开本机。** 任何版本不得上传音频（除非用户明确改选全云）。
2. **API Key 存 Android Keystore 加密存储**，不进日志、不进备份、不进崩溃上报。
3. **发送前可见**：首次调用某 provider 前，把将要发送的内容显示给用户看一眼。
4. **断网可用**：录音照录、本地转写照跑、小说化进工作队列等联网。

其他：`android:allowBackup=false`（内容私密，不参与自动备份）；日志默认脱敏（正文只打长度）。

## 11. 界面结构

```
底部导航：[日历] [全部] [设置]
        ↘ 中央/首页大按钮：开始录音（红）

日历 ──点格子──▶ 当日列表 ──▶ 详情
全部 ──点条目──▶ 详情
录音 ──▶ 录音中 ──▶ 追问"还有吗" ──▶ 详情
```

| 屏幕 | 要点 |
|---|---|
| 日历（首屏） | 月视图红点、顶部搜索、底部录音钮、下拉回到今天 |
| 录音中 | 全屏极暗、波形、计时、暂停/继续、音量键可结束 |
| 追问"还有吗" | 30 秒倒计时、只轻震、超时自动收起 |
| 全部 | 时间轴 / 卡片流切换（记住选择） |
| 详情 | tab：原样 / 小说化·补写N处 / 标签 / 素材（占位）；底部常驻播放条 |
| 逐段对照 | 模型补写处高亮 +「补写 6 处」清单 |
| 编辑 | 就地编辑，保存即新版本，标"已手改" |
| 生成中/失败 | 可离开，列表内显示状态徽标，可重试 |
| 设置 | Provider/Key/模型、转写引擎、夜间行为、标签管理、回收站、用量 |
| 标签管理 | 重命名、合并、删除；按 kind 分组 |

### 夜间体验特则（这是产品的一部分，不是配色）

- 深色常驻，全流程无白闪（含启动页）。
- 动画最小化；不用纯白，用低亮度琥珀/暗红。
- 不发声，只轻震一次。
- 30 秒无操作自动收起并熄屏。
- 设置里可关（默认开）。

## 13. 技术选型与工程约定

| 项 | 选择 | 理由 |
|---|---|---|
| 语言/UI | Kotlin + Compose | 单人可以最快迭代 |
| SDK | compileSdk/targetSdk 36，minSdk 26 | 对齐本机已装 build-tools 36；minSdk 26 覆盖 Composable 生态且省兼容代码 |
| 持久化 | Room | 搜索与标签关联天然合适 |
| 设置 | DataStore (Proto/Preferences) | 类型安全 |
| 密钥 | Keystore + AES-GCM | 系统级 |
| 网络 | OkHttp + kotlinx.serialization | 轻，流式方便 |
| 后台 | WorkManager（生成排队）+ ForegroundService（录音） | 断网续跑 |
| 图片 | Coil | 未来插画直接用 |
| 架构 | **单 module + 包边界**（data / domain / llm / ui） | 一人维护，多 module 拖慢迭代；边界靠包与接口约束，等第二个人再拆 |
| 测试 | JUnit + Turbine + Robolectric；UI 用 Roborazzi 截图 | JVM 上跑，CI 友好 |
| 构建 | Gradle CLI 为主，Android Studio 为辅 | 便于自动化验证 |

**验证闭环（无需人肉点屏）**：Gradle 构建 → `adb install` → uiautomator dump / mobile-mcp 驱动 → `adb exec-out screencap` 截图逐张核对 → `adb logcat` 定位。

## 14. 验收标准

- [ ] 从点亮屏幕到开始录音 ≤ 3 步，≤ 3 秒。
- [ ] 录音过程中接电话/切后台/锁屏，音频不丢。
- [ ] 原样稿 diff 违规次数 = 0（评测集 20 条）。
- [ ] 小说化评测集：≥ 8/10 条被判"像人写的"；编造事实率 ≤ 10%。
- [ ] 1000 条记录下，日历与列表滚动不掉帧（基准机：本机模拟器 + 一台真机）。
- [ ] 飞行模式下：可录音、可本地转写、小说化进队列并在恢复网络后自动完成。
- [ ] 抓包验证：全程无音频外传。
