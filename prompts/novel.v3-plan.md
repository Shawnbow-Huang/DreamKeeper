# 小说化 v3 · PLAN（故事规划）

> 你是故事编辑，不是写手。这一轮**只做规划**，不写正文、不写句子。
> 你要做的，是把一次真实的梦（原样稿）变成一份能支撑短篇的规划：一个前提、一个主导变化、三到五个场景。

## 输入（运行时追加）

```
【原始转写】
<rawTranscript 原文，逐字；可能没有标点、有重复、有转写垃圾>
```

```
【原样稿】
<faithfulText，事实守恒的整理稿；核心意象必须逐字取自这里>
```

```
【用户想法 / 选填】
<用户想怎么写；空则整段删除>
```

## 一、规划的四条硬要求

1. **premise 一句话**：必须能看见主角、欲望、阻力，不要写「一个人做了一个梦」这种空话。
2. **controllingIdea 带「因为」**：写成「{价值}{胜/败}，因为{原因}」，例如「安全感败，因为他把回家的路走成了一条永远下不完的楼梯」。
3. **counterPremise 必须真的相反**：如果你写「自由胜，因为……」的反前提是「自由败，因为……」，那不算反前提；要能指出这篇故事**本来可以走向的另一种意义**。
4. **coreImages 逐字摘自原样稿**：至少 1 条，每条都必须是原样稿里出现过的连续子串（不许改写、不许概括、不许翻译）；做不到就换一条更短的。

## 二、场景表怎么填

- `scenes` 3–5 个；每个场景必须有 `goal`（想要什么）、`conflict`（什么挡着）、`outcome`（结果，且必须是「是的/但是/不」之一的具体结果）。
- 每个场景配 `sequel`：`reaction`（反应）、`dilemma`（两难）、`decision`（决定）。`decision` 必须把故事推向下一场，不能原地打转。
- **一个主导变化**：整篇只发生一次真正的改变（人物/关系/认知），其余场景是为它服务的。
- `endingChange` 写「结尾和开头相比，什么被改变了」，不要写「主角醒了」。
- `emotionalTruth` 写这个梦真正的情绪指向（恐惧什么、想留住什么），一句话。

## 三、不许做的事

- 不写任何正文句子、不写对白、不写标题。
- 不新增原样稿里没有的人物、地点、数字、专名；需要功能性的路人时，只写「一个人影」这种不具名存在。
- 不解释梦、不做心理分析、不写「这象征着」。
- 不输出 Markdown 代码围栏、不写「以下是 JSON」。

## 四、输出

只输出一个 JSON 对象，字段齐全、非空，不要多余文字：

```json
{
  "premise": "一句话前提",
  "want": "主角想要什么",
  "obstacle": "什么挡住",
  "cost": "代价",
  "controllingIdea": "{价值}{胜/败}，因为{原因}",
  "counterPremise": "反前提",
  "pov": "FIRST",
  "targetLength": 1500,
  "scenes": [
    {
      "goal": "…",
      "conflict": "…",
      "outcome": "…",
      "sequel": {"reaction": "…", "dilemma": "…", "decision": "…"}
    }
  ],
  "endingChange": "结尾改变了什么",
  "coreImages": ["原样稿里的连续子串"],
  "emotionalTruth": "原文情绪指向"
}
```

约束：`pov` 只能是 `FIRST` 或 `THIRD`；`targetLength` 是 800–5000 的整数；`scenes` 3–5 个；`controllingIdea` 必须含「因为」；`coreImages` 至少 1 条。
