# prompts/ · 变更记录

提示词的唯一真源是文件本身：版本 = 文件名（`vX.Y`）+ 内容 sha256（偏差 D5、D55）。
**旧版本永久保留、一字节不覆盖**：改一次就多一个文件，这里记一行。回滚不靠改文件，靠让运行时指向旧文件。

## 口径

- `sha256_8` = 文件内容 SHA-256 的前 8 位（小写十六进制）。复算：

  ```bash
  python -c "import hashlib,sys;print(hashlib.sha256(open(sys.argv[1],'rb').read()).hexdigest()[:8])" prompts/novel.v1.1.md
  ```

- 文件按 UTF-8 存、LF 换行、无 BOM。换行符或 BOM 一变哈希就变——所以哈希同时是一条一致性检查。
- 版本号：文件名 `vX.Y`，YAML 头 `version` 同名（`v1.2`，沿用 v1 的 `v` 前缀）。
  **v1.x 内只允许**改措辞、结构与自检写法，以及**纯增量、不破坏既有键**的 schema 微调（v1.2 给 `changeLog` 加 `quote` 即属此类）。
  **删键、改名、改事实契约、改 `temperature`** 必须开 v2。（原口径「改 schema 必须开 v2」由 v1.2 修订，理由见下文 v1.2 节。）
- 本文件**不记录自己的哈希**（会循环）。它只记别的文件的。

### 1. `prompts/novel.v1.2.md` — sha256_8 `6bc530c8`

**改了什么**（唯一实质变更：`changeLog` 每条 `{type, detail}` → `{type, detail, quote}`）

1. YAML 头：`version: v1.1 → v1.2`，`file` / `sourceOfTruth` 指向新文件；`outputSchema` 的 `changeLog` 条目加 `"quote": string`。`temperature: 0.9`、`design` 一字未改。
2. 版本注记：保留 v1.1 那行注释，追加一行说明本次只动 `changeLog`；标题与 §六 变更记录同步加 v1.2 条目。
3. §四 JSON 示例：两条 `changeLog` 都带 `quote`（`"楼道很暗，声控灯要跺脚才亮"`、`"后来电梯门开了，外面不是楼道"`），`detail` 里不再用「」夹原句。
4. §四 约束：原「两个键 + `detail` 内嵌原句」三条改成四条——
   - 顶层四字段那句改为「顶层字段四个 + `changeLog` 每条三个键」；
   - 每条**只有三个键** `type` / `detail` / `quote`，缺一不可，也不许出现第四个键；
   - `detail`：只写**改了什么**，不塞原句；
   - `quote`：rawTranscript 的**逐字连续 4–40 字**原文，App 用 `rawTranscript.indexOf(quote)` 定位并高亮**首个**命中，**找不到就整条丢弃**；禁止编造、改字、跨段拼接、省略号缩写、空串。
5. §五 自检 5.6 的第 36、37 条改为点名 `quote` 与三键：`quote` 必须能 `indexOf` 命中（命中不了的条目等于没报，宁可删掉这一条）；JSON 可解析、顶层四字段齐全、每条三键齐全且无多余键、`detail` 不夹原句。自检**仍是 39 项**，只改措辞、不加项。

**为什么改**

- v1.1 把 D41 的 quote 口径压进 `detail`，要求原句用「」括起来，再由 App 从 `detail` 里抠。这是**脆弱约定**：模型漏写引号，高亮就**静默消失**——「没写」和「找不到」在界面上是同一个结果，而且没法确定性校验。
- 显式字段把它变成可断言的：`quote` 是一个独立字符串，长度区间与 `indexOf` 命中都能直接验，失败就整条丢弃并计数，不需要猜；`detail` 回归纯人读说明。两个职责分开，也顺带堵住「在 detail 里写了原句却忘了加引号」这类半对半错的输出。
- 与设计 §6.2 / D41 的原文逐字对齐：`{type, detail, quote}`、4–40 字、`indexOf` 首个命中、**不引入字符偏移**。

**未放宽**：事实契约（§二 允许 6 条 / 禁止 6 条、补写边界）、风格契约 A1–A21（HARD 7 / MED 9 / SOFT 5）、§3.4 正向要求 8 条、`temperature: 0.9`、顶层四字段——与 v1.1 等价，只改了 `changeLog` 的条目结构。

### 2. 版本口径的一处修订（本文件「口径」节）

原口径写「改输出 schema、改事实契约、加删字段，必须开 v2」。v1.2 是**纯增量**的 schema 微调：只加一个键，既有 `type` / `detail` 语义不变，事实契约与风格契约一个字没动。按原口径会给一个「契约没变却跳大版本」的错信号，所以口径改为「v1.x 内允许纯增量、不破坏既有键的 schema 微调；删键、改名、改事实契约、改 `temperature` 仍必须开 v2」。

**`novel.v1.1.md` 的 `dc5f1374` 仍有效、继续留档**：该文件一个字节都没被碰，回滚只要让运行时指向它。v1.1 节里「quote 口径落进 `detail`」那句保留为历史记录，**不再代表现行 schema**。

6. 自检 39 → **46 项**（事实 10 / HARD 8 / MED 9 / SOFT 6 / JSON 7 / 长度 6）。

**为什么改**

- §7.2 把去 AI 味定成四层，v1.2 的「按号点名」只是黑名单一层，缺契约层与正例。模型拿到的仍是「别写这些」，于是绕开词表继续机器腔。
- MED 类规则只写「不要」没有用：密度类必须给数字，否则「少用破折号」在模型那里等于「随便用」。v2 让每一条都能被逐字判定。
- G1 在补场景这一侧最容易破：写「空」和「远」最省事的办法就是加颜色与方位。所以 2.3 把 G1 翻成一句可执行的话——用光、温度、声音、身体感觉，别用新坐标。
- 示例是 `quote` 规则唯一能被对照检验的地方；v1.2 只有文字描述，模型很容易「大致记得」而拼接原句。

**未放宽**：五条禁止、`quote` 逐字 4–40、四字段、`temperature: 0.9` 均与 v1.2 一致；3.1 的七条比 v1.2 更具体（点名到句式与替代写法），不构成放权。

### 3. `prompts/novel_revise.v1.md` — sha256_8 `2ebba630`

**改了什么**（新文件）

1. 三条硬原则落成可验收条款：最小改动（3.3 的 ≤115% + 3.2 未涉及段落逐字不变 + 3.1 连带上限前后各 ≤1 段、合计 ≤3 句）、歧义先问（第五节）、每版可撤回（6.4 明确「不改也要交一版」）。
2. **「必要连带」第一次被定义**：人称 / 指代 / 相邻一句过渡 / 该段标点分段，四种，没有第五种。
3. 改稿特有的事实禁令三条：不许借改稿改事实、不许把意见当授权扩写、不许借连带修别的问题。
4. ASK 判据可执行：5.1 两条同时成立才问；5.2 列五种不许问的情形；**「问过一次就必须改」设为最高优先级**；5.3 规定只问一个、≤40 字、必须带两个具体候选、不许夹带方案。
5. **六个快捷按钮的默认解读表**（5.4）：太文绉绉 / 细节太多 / 结尾太说教 / 人称不对 / 多点环境 / 少点形容，各自写清允许动与不许动的地方。
6. `changeLog` **合并规则**（6.3）：输出这一版的全量清单（旧条目保留、受影响条目替换、失效条目删除）。理由是 UI 用数组长度显示「补写 N 处」，追加式增长会虚报。
7. 自检 **40 项**（最小改动 10 / 长度与事实 10 / 风格继承 8 / JSON 9 / 兜底 3）。

**为什么改**

- §6.3 之前只有「整体重生成」一条路：用户说「结尾太说教」，模型会重写全篇，版与版之间没法对比，撤回也失去意义。改稿要成立，先得有「只动一处」的可判定边界。
- 「最小改动」若只是口号，模型会用同义替换冒充改动、或顺手润色未涉及的段落；3.2 与 7.1 把「未涉及段落逐字相同」写成硬验收，才拦得住。
- 快捷按钮是高频输入但**不是坐标**：不把六种按钮的默认解读固定下来，每按一次都要问一轮，等于把对话改稿做成问卷。
- ASK 只在「猜错就推翻一整版」时使用；没有 5.2 的五种例外，模型会退化成「什么都没听懂就先问」，把一轮能改完的事拖成两轮。

**未放宽**：`temperature: 0.3`（设计 §7.1）；115% 是硬上限；事实契约与 A1–A21 只继承不重写，避免两份文件各自演化。
