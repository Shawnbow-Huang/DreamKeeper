# prompts/ · 变更记录

提示词的唯一真源是文件本身：版本 = 文件名（`vX.Y`）+ 内容 sha256（偏差 D5、D55）。
**旧版本永久保留、一字节不覆盖**：改一次就多一个文件，这里记一行。回滚不靠改文件，靠让运行时指向旧文件。

## 口径

- `sha256_8` = 文件内容 SHA-256 的前 8 位（小写十六进制）。复算：

  ```bash
  python -c "import hashlib,sys;print(hashlib.sha256(open(sys.argv[1],'rb').read()).hexdigest()[:8])" prompts/novel.v1.1.md
  ```

- 文件按 UTF-8 存、LF 换行、无 BOM。换行符或 BOM 一变哈希就变——所以哈希同时是一条一致性检查。
- 版本号：文件名 `vX.Y`，YAML 头 `version` 同名（`v1.1`，沿用 v1 的 `v` 前缀）。
  **v1 → v1.1 只允许改措辞、结构与自检写法**；改输出 schema、改事实契约、加删字段，必须开 v2。
- 本文件**不记录自己的哈希**（会循环）。它只记别的文件的。

### 1. `prompts/novel.v1.1.md` — sha256_8 `dc5f1374`

**改了什么**

1. YAML 头：`version: v1 → v1.1`，`file` / `sourceOfTruth` 指向新文件。`outputSchema`、`temperature: 0.9`、`design` 一字未改。
2. 标题后加「对齐口径」两行：规则来源、严重度分布，并写明脚本是前置闸门（HARD > 0 直接退出码 1）且**放行 ≠ 像人写的**。
3. §三 风格契约重排为三级，v1 散在 A/B 两节的禁用词与「必须保留」并入，**未删项**：
   - **3.1 HARD 7 条**（A1 / A2 / A4 / A5 / A6 / A7 / A16）：**逐条点名**要避开的字面句式，每条附一句改法；A1 注明只查末段，A4 注明「我没明白」不判、「我明白」判。
   - **3.2 MED 9 条**（A3 / A8 / A9 / A10 / A11 / A12 / A13 / A15 / A18）：给**判定口径与阈值**（≥3 分句共享 ≥2 字前缀、连续 3 段 ≥40 字且差 <10%、一段 ≥4 句且差 <20%、破折号密度公式），不因单词定罪。
   - **3.3 SOFT 5 条**（A14 / A17 / A19 / A20 / A21）：只提醒、不硬禁，要求「命中要能说出这里为什么必须这么写」。
4. 新增 **§3.4 正向要求 8 条**，首四条即「保留不确定 / 句长参差 / 不解释隐喻 / 不把跳跃处讲圆」，另含口语留存、第一人称过去时、细节不编造、篇幅与标题。
5. §五 自检从 6 条扩到 **39 项逐条核对**：事实 5 + HARD 7 + MED 9 + SOFT 5 + 正向 8 + 清单格式 5，每项与 A 编号对齐。
6. §四 输出格式：`changeLog` 仍是 `{type, detail}` 两个键，**不加字段**；D41 的 quote 口径落进 `detail`——每条必须内嵌 4–40 字、能在 rawTranscript 里逐字命中的原句片段（用「」括起），供 `indexOf` 定位高亮。

**为什么改**

- **闸门就是脚本**：HARD 命中直接判失败。v1 的禁用词与 A1–A21 只部分重合——A16 元话语整类、A5 的「好像全世界 / 宛如万物」变体，v1 都没点名；模型按 v1 改完仍会挂在 `check-ai-flavor.py` 上。
- **v1 把「禁用词」和「密度类规则」混在一节**，模型分不清「出现即重写」与「按密度判断」；实际后果是两头都软——该重写的没改，该放行的删了。分级是为了让处置动作唯一。
- **正向要求此前只存在于 `docs/eval/anti-ai-patterns.md`**，提示词里没有。只给罚则，输出会趋向「每句都合规、通篇不像人写」。
- **自检不给编号**，模型无法对着脚本命中行改；39 项与 A 编号一一对应后可逐行定位。

### 2. `prompts/faithful_cleanup.v1.1.md` — sha256_8 `b9fa7fb7`

**改了什么**

1. YAML 头同上更新；`temperature: 0.1`、`outputSchema: text/plain` 未改。
2. 新增 **§2.1 优先级**：去 AI 味规则与事实契约冲突时事实契约优先；点名四种最常见的越界改写（删「不禁」、删看起来像升华的结尾、把「然后」换成时间词、把「然而」换成「但是」），并说明 diff 硬校验会原样抓住。
3. §三 改为「A1–A21 在本模式的作用域」：
   - **3.0 作用域声明**：A 规则只作用于**标点、空白、分段**；需要换词/加词才能触发的规则不产生修改权。
   - **3.1 HARD 7 条**逐条点名，处置统一为「原文有 → 原样保留；原文没有 → 一个字都不许加」，A16 例外（口述里不会有「以下是」，出现即违规）。
   - **3.2 MED 9 条拆两组**：插入标点能触发的 3 条（A10 破折号 ≤2 处 / A11 分段不按字数 / A12 断句按气口）才是本模式真正要守的；需要换词才能触发的 6 条（A3 / A8 / A9 / A13 / A15 / A18）被事实契约禁止，不重复授权。
   - **3.3 SOFT 5 条**：提醒，一律不许动（含「不许把『然而』换『但是』」这类同义替换禁令）。
4. 新增 **§3.4 正向要求 6 条**：保留不确定词、句长由气口决定、不解释隐喻、不讲圆跳跃、口语全部保留、输出长度 ≈ 输入长度。
5. §五 自检从 5 条扩到 **31 项**：字 3 + HARD 7 + MED 9 + SOFT 5 + 正向 6 + 兜底 1。

**为什么改**

- v1 只有一张「书面化替换词」小表，与 21 条几乎不重合；但**直接把 A 规则搬进来会引发反向失败**：模型为了「去 AI 味」去删用户的「不禁」「原来如此」，把一份 0 违规的稿子改成违约。所以 v1.1 的重点是**划作用域**，不是加罚则。
- 本模式里真正由 AI 决定的只有标点和分段，因此 21 条里只有 **A10 / A11 / A12** 有实际修改意义；v1 对这一点只有一句笼统的「不要变通顺」。
- **A16 是唯一「出现必然是你写的」的 HARD**，必须单独点名，否则会被当成一般风格建议而放过。
